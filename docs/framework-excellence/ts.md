# Neutron TypeScript Meta-Framework — Excellence Scaffold (to 10/10)

Audit date: 2026-06-05
Package: `@neutron-build/core` (`typescript/packages/neutron`, v0.1.3)
Real-usage refs: `typescript/apps/site`, `typescript/apps/playground`
Tests at audit: **223 passing / 36 files** (`vitest run`), all green in 2.1s.
Method: read implementation (not READMEs/types), ran the suite, traced the dev + production render paths, the islands/hydration pipeline, adapters, and the cross-SDK Nucleus client.

**Verdict: 6.5 / 10.** This is a real, surprisingly complete SSR meta-framework — not a stub. The data pipeline (parallel loaders, credential-aware response cache, single-flight dedup, ETag revalidation, SPA partial-data fetch with route-diffing) is genuinely strong and in places ahead of Remix's defaults. But it falls short of the category leaders on three structural axes: (1) **two divergent render paths** (dev Vite-middleware vs a generated production `entry.node.ts`) that don't share streaming, head, or error behavior; (2) a **regex-based island system that is not production-safe** and is half-superseded by a second `<Island>` component system; and (3) **contract non-conformance** — no `/health`, middleware order not enforced, no graceful drain in the generated entry. The Nucleus client carries the cross-SDK comma-split corruption bug and has zero real-DB test coverage.

## 1. Architecture map — what is REAL vs partial vs stub

| Loaders / actions data flow | **Real, strong** | `server/index.ts:801` parallel loaders via `Promise.all` (test proves 4.8x), action-before-loaders, `Response`-throw escape hatch, per-route loader cache. |
| App-response cache | **Real, careful** | `server/index.ts:535` credential-aware keying, `:556` single-flight dedup, `:1610` `maybeStoreAppResponse` refuses `Set-Cookie`/`private`/CORS responses. Security comments are accurate. |
| SPA navigation / partial data | **Real, ahead of baseline** | `client/hydrate.ts:442` diff-based `X-Neutron-Routes` so only changed segments re-run loaders; abort-controller race handling; CSS-before-swap to prevent FOUC. |
| Streaming SSR | **Real but path-split** | `server/index.ts:1034` `renderToReadableStream` — **only in `createServer` (dev/fallback)**. The production `entry.node.ts` uses blocking `renderToString` (see §3). |
| Islands (directive) | **Partial / not production-safe** | `vite/island-transform.ts:28` regex `clientDirectivePattern` — breaks on multiline JSX, `>` in prop values, `}` in expressions; `transformedCode` is never modified (returns input unchanged). |
| Islands (`<Island>` component) | **Real, second system** | `client/island.tsx` + `vite/island-plugin.ts` — a parallel, component-based island path. Two systems, unclear which is canonical. |
| Island hydration runtime | **Real** | `vite/island-transform.ts:173` load/visible/idle/media/only, IntersectionObserver, prototype-pollution guard on props. |
| Signals | **Thin wrapper** | `client/signals.ts` re-exports `@preact/signals-core` + `untrack`/`readonly`. Fine, but `untrack` via `batch` is **not** true untracking — it still subscribes. |
| Content collections | **Real** | `content/index.ts` `defineCollection`/`getCollection`/`getEntry`, zod schema, MDX, TOC, reading-time, sanitize. |
| SEO / head | **Real, good** | `core/seo.ts` structured `SeoMetaInput` merge across layout chain, escaped; raw-string escape hatch. |

| Image optimization | **Real** | `server/image-optimizer.ts` sharp-based, cache dir, `/_neutron/image`. |

## 2. Idiomaticity / quality verdict (file:line evidence)

**Strong, idiomatic code:**
- `core/router.ts` — clean trie, correct param backtracking (`:94` deletes params on miss). Best-in-class for a hand-rolled matcher.
- `server/index.ts:535-597` — the cache + single-flight section is the best code in the repo. The security reasoning (no shared cache for credentialed requests, no CORS-reflected storage) is correct and rare to see done right.
- `client/hydrate.ts:442-573` — navigation with abort/race guards (`latestNavigationRequestId`), CSS-timeout safety-valve full reload (`:540`), hydration-failure keeps SSR HTML (`:315`). Genuinely production-minded.

**Weak / non-idiomatic:**
- `vite/island-transform.ts:28` — regex JSX parsing. The directive regex `[^>]*?` cannot span newlines or nested `>`; `extractProps` JSON-parses `{...}` props (`:115`) which will silently drop any non-literal expression. This is the single biggest correctness liability.
- `vite/island-plugin.ts:29` and `:36` — more regex import resolution; `generateBundle` emits chunks but nothing rewrites call sites to lazy-load them, so the "separate island chunk" is dead weight.
- `core/manifest.ts:250-277` — regex config extraction duplicates logic the Vite/Babel AST already has. `extractConfigObjectLiteral` (`:290`) hand-rolls a brace matcher with naive string skipping — a `}` inside a template-literal `${}` interpolation breaks it.
- `client/hydrate.ts:347` `applyHeadHtml` — regex-parses server head HTML (`<title>`, `<meta>`) on the client to sync `<head>` during SPA nav. Fragile and duplicates `core/seo.ts`. Should ship structured head data in the JSON payload, not re-parse HTML.
- Two near-identical `renderDefaultError`/`wrapHtml`/head-resolution implementations exist in `server/index.ts` and `vite/plugin.ts`. They drift (e.g. prod hides stack at `server/index.ts:1836`, dev shows it at `vite/plugin.ts:959`). One renderer should be shared.

**Type safety:** `RouteModule` default is cast `as any` at every render site (`server/index.ts:978`, `render-static.ts:94`, `vite/plugin.ts:785`). Typed routes exist (`core/typed-routes.ts`, `route-typegen.ts`) but `writeRouteTypes` defaults **off** (`vite/plugin.ts:114`), so the typed-link DX is opt-in and unused by the apps.

## 3. The two-render-path problem (systemic, severity HIGH)

There are **three** code paths that render a route, and they are not unified:

1. **Dev** — `vite/plugin.ts:626` `handleRequest` (Vite middleware, `ssrLoadModule`).
2. **Fallback prod server** — `server/index.ts:248` `createServer` / `startServer` (`neutron/server`): spins up a **full Vite server in middleware mode at runtime** (`server/index.ts:1678` `createSsrServer`) and `ssrLoadModule`s routes per request. This is a dev server in production. It *does* stream (`:1067`).
3. **Adapter-built prod entry** — `neutron-cli/build.ts:1040` generates `entry.node.ts` with static route imports and **no Vite** (correct for prod), but uses blocking `renderToString` and omits streaming, `/health`, and drain.

Consequences:
- Streaming SSR is advertised but only path #1/#2 stream; the actual deployable artifact (#3) does not.
- Head resolution, error boundaries, and the data-script/CSP-nonce wiring are re-implemented in each path and drift.
- `startServer` (#2) is a trap: a user who runs `neutron/server` directly ships Vite + the whole dev toolchain to production.

**This must collapse to one render core** that every path calls. See Phase 1.

## 5. Concrete issues (file:line + severity)

### CRITICAL
1. **KV/Document collection reads corrupt comma values** — `neutron-nucleus/src/kv/index.ts:274` (`lrange`), `:314` (`hgetall`), `:344` (`smembers`), `:368`/`:375` (`zrange`/`zrangeByScore`), and `document/index.ts:104`. Server returns a delimited string; client `raw.split(',')` shreds any element containing a comma. Ported across SDKs. **Fix at the wire layer** (see Phase 5).
2. **No `/health` endpoint** — required by `FRAMEWORK_CONTRACT.md §7` (`GET /health → {status:"ok", nucleus:bool, version}`). Absent from `server/index.ts`, the generated entry, and apps. Grep proof: only hit is a rate-limit doc comment.
3. **Production entry ships no streaming and no graceful shutdown** — `neutron-cli/build.ts` `generateRuntimeEntrySource` uses `renderToString`; `createServer`'s `startServer` calls `process.exit(0)` immediately (`server/index.ts:2076`) with **no 30s drain** (contract §8).

### HIGH
4. **Island JSX transform is regex-based** — `vite/island-transform.ts:28`. Multiline elements, `>`/`}` in props, and expression props all break or silently drop. `transformedCode` is returned unmodified (`:55`), so the transform doesn't even rewrite the source.
5. **Middleware order not enforced** — there is no default global stack. `core/middleware.ts` only runs user-supplied per-route fns. The contract's 10-layer order (RequestID→Logging→Recovery→CORS→Compression→RateLimit→Auth→Timeout→OTel) is documented but unimplemented; the apps wire CORS/compress ad hoc in `createServer` in the wrong order (compression before CORS at `server/index.ts:315` vs contract CORS-before-Compression).
6. **`startServer` runs Vite in production** — `server/index.ts:1678`. Foot-gun; should be removed or gated behind an explicit dev flag.
7. **Three duplicated renderers drift** — `server/index.ts` vs `vite/plugin.ts` vs generated entry. Stack-trace exposure already diverges.
8. **Plain-Postgres path loses fidelity** — `features.ts:24` disables all non-SQL models on plain PG (correct), but the SQL transport still assumes Nucleus quirks; there is no test that the SQL surface works against stock Postgres ("any Postgres client works" is unverified).
9. **No real-DB integration tier** — `integration.test.ts:59` `WireTransport`/`MockTransport` only. DB SQL correctness is asserted against hand-written mock responses.

### MEDIUM
10. **`untrack` doesn't untrack** — `client/signals.ts` wraps `batch`, which still subscribes. Misleading API.
11. **Route config via regex** — `core/manifest.ts:242` misses computed/spread config; `extractConfigObjectLiteral:290` breaks on `${}` in template literals.
12. **Client-side head sync re-parses HTML** — `client/hydrate.ts:347`. Ship structured head in JSON instead.
13. **rss.xml GET-handler routes not prerendered by static adapter** (known) — API/`GET`-handler routes are stripped as server-only (`server-only.ts:14`) and the static renderer (`render-static.ts:60`) only renders `mode:"static"` page components, so `rss.xml.ts` produces no file under the static adapter.
14. **Typed routes off by default** — `vite/plugin.ts:114` `writeRouteTypes` defaults false; flagship DX unused.
15. **`island-plugin.ts` emits dead chunks** — `generateBundle` (`:60`) creates island chunks no call site references.

### LOW
16. Default `<html lang="en">` hardcoded in 3 places (`render-static.ts:206`, `server/index.ts:1912`, `vite/plugin.ts`); ignores i18n.
17. `getClientEntryScriptSrc` picks "last sorted index-\*.js" (`server/index.ts:1966`) — brittle if multiple entries.

## 6. Phased, file-level implementation plan to 10/10

Principle: **one render core, one island system, contract-conformant edges, real DB tests.** Every phase ships with tests + acceptance criteria.

### Phase 1 — Unify the render core (collapses §3, fixes #6, #7)
**Goal:** one function renders a route everywhere; dev/prod/edge differ only in module loading + streaming primitive.

- **New file** `src/core/render-route.ts` — `renderRoute(ctx: RenderContext): Promise<Response>` where `RenderContext` carries: resolved route chain, a `loadModule(routeId) => RouteModule` injected by the caller, `stream: boolean`, `clientEntryScriptSrc`, `nonce`, hooks. Move ALL of: action dispatch, parallel loaders + loader cache, head resolution, error-boundary selection, data-script + CSP-nonce emission, and the JSON/HTML branch here. Single `wrapHtml`/`buildHtmlPrefix`/`buildHtmlSuffix` live here.
- **Refactor** `server/index.ts:658` `handleAppRouteRequest`, `vite/plugin.ts:626` `handleRequest`, and `neutron-cli/build.ts` `generateRuntimeEntrySource` to all call `renderRoute`. Caller supplies `loadModule` (Vite `ssrLoadModule` in dev, static `ROUTES_BY_ID` map in prod entry).
- **Delete** the duplicate `renderDefaultError`/`wrapHtml`/`resolveRouteHeadHtml` copies in `server/index.ts` and `vite/plugin.ts`.
- **Remove or gate** `createSsrServer`/runtime-Vite from `startServer` (`server/index.ts:1678`): `startServer` should serve the **adapter-built node entry**, never Vite. If kept for `neutron dev`, rename to `createDevServer` and never export from `neutron/server`.
- **Streaming in the prod entry:** make `generateRuntimeEntrySource` import `renderToReadableStream` from `@neutron-build/core/runtime-edge` and stream by default, falling back to `renderToString` only when the stream import is unavailable (mirror `server/index.ts:1059`).

**Tests:** `src/core/render-route.test.ts` — golden HTML + JSON output for: static page, nested layout, action+loader, loader-throws-Response, render error → boundary, streaming vs non-streaming produce byte-identical final HTML. Run the same assertions through all three callers (parametrized) to prove convergence.
**Acceptance:** dev, `startServer`, and the generated entry emit identical HTML for the playground's `/dashboard`, `/todos`, `/users/[id]` (diff = 0). No `vite` import reachable from `@neutron-build/core/server`.

### Phase 2 — Contract conformance: default stack, `/health`, graceful drain (fixes #2, #3, #5)
- **New file** `src/server/default-stack.ts` — `createDefaultStack(opts)` returning middleware in the **exact contract order**: `requestId → logging → recovery → cors → compression → rateLimit → auth → timeout → otel`. Each layer is a `MiddlewareFn`; `recovery` catches and renders RFC-7807. Export a `composeContractStack(userMiddleware[])` that interleaves user middleware after `auth`.
- **New file** `src/server/health.ts` — `healthHandler({ nucleus }) => Response` returning **exactly** `{ status: "ok", nucleus: boolean, version: string }` (version from `package.json`). Wire `GET /health` in `createServer` (`server/index.ts:366` area, before the catch-all) and in `generateRuntimeEntrySource`.
- **Graceful shutdown:** add a 30s drain to both `startServer` (`server/index.ts:2070`) and the generated node entry: stop accepting new connections, await in-flight (`appInFlightRequests`), then exit. SIGTERM/SIGINT.
- **Reorder** the ad-hoc `createServer` middleware so CORS precedes compression (currently `:315` compress, `:319` cors) — or replace entirely with `createDefaultStack`.

**Tests:** `src/server/default-stack.test.ts` asserts the emitted order by tagging each layer and recording call sequence; `health.test.ts` asserts the exact JSON shape and that `nucleus` reflects a probe. A contract test reads `FRAMEWORK_CONTRACT.md §5` order as data and asserts the stack matches.
**Acceptance:** `GET /health` returns the contract body byte-for-byte; ordering test passes; killing the server mid-request drains instead of dropping.

### Phase 3 — One island system, AST-based (fixes #4, #15)
- **Pick the component API** (`client/island.tsx`) as canonical; keep the `client:` directive **as sugar compiled to it via AST**.
- **Rewrite** `vite/island-transform.ts` to parse with `@babel/parser` (already a dep) + walk JSX. For each element with a `client:*` attribute: hoist the component import, replace the element with `<Island component={X} client="..." {...props}/>`, and serialize props by **evaluating literal-safe expressions only**, erroring (with file:line) on non-serializable props instead of silently dropping. Use `magic-string` (already used in `server-only.ts`) for surgical edits.
- **Lazy-load island chunks:** in `vite/island-plugin.ts`, rewrite island call sites to `import()` the component chunk on hydration (so SSR includes markup, client downloads only the hydrated islands). Wire `generateBundle` chunks to a manifest the runtime reads.
- **Delete** the dead `transformedCode` no-op and the regex `island-plugin.ts:29` resolution.

**Tests:** `src/vite/island-transform.test.ts` — multiline elements, `>`/`}` in prop values, expression props (must error clearly), nested islands, island inside Nav/Footer. Snapshot the rewritten AST output. `e2e`: hydrate a `client:visible` island in `apps/playground/src/routes/islands.tsx` and assert only that chunk loads.
**Acceptance:** every directive form in playground hydrates; non-serializable prop produces a build error pointing at the source line; island JS is code-split (separate chunk in `dist/assets`).

### Phase 4 — DX/type-safety + head correctness (fixes #1-config, #10, #11, #12, #14)
- **Typed routes on by default** — flip `writeRouteTypes` default to `true` in `vite/plugin.ts`; have `<Link href>` and `navigate()` consume the generated `RouteHref` union. Cast-free render: thread a typed `RouteModule<TData>` so `data` is inferred per route.
- **AST route config** — replace `core/manifest.ts:242` regex with a Babel parse of the `config` export (reuse the `server-only.ts` AST helpers). Support computed values by evaluating in the SSR module graph at build (read `module.config`) rather than scraping source.
- **Structured head over the wire** — in the JSON payload (`server/index.ts:965`), send `__head__` as structured `SeoMetaInput`, and replace `client/hydrate.ts:347` `applyHeadHtml` regex parsing with a `applyHead(seo)` that mirrors `core/seo.ts` semantics. Delete the HTML re-parse.
- **Fix `untrack`** — implement real untracking (read `.peek()` / use signals' untracked read), not `batch`.

**Tests:** typegen test asserts `Link` to an unknown route is a type error (tsd/expect-type); config test parses computed `mode`; head test asserts SPA nav updates title/meta/canonical from structured data with no HTML regex.
**Acceptance:** `tsc --noEmit` is clean with zero `as any` at render sites; broken `<Link>` fails typecheck; SPA head updates match SSR head exactly.

### Phase 5 — Nucleus client correctness + real-DB tier (fixes #1, #8, #9)
- **Fix comma corruption at the wire layer.** The root cause is the server returning a single delimited scalar for multi-value reads. Change `LRANGE`/`HGETALL`/`SMEMBERS`/`ZRANGE`/`ZRANGEBYSCORE` (and `document` list) to return a **typed array / jsonb** over pgwire and have the client read `transport.query` rows, not `fetchval` + `split(',')`. Update `kv/index.ts:270-376` and `document/index.ts:104`. If the server contract can't change immediately, switch the delimiter to a length-prefixed or `\x00`-joined encoding and decode it — but the array return is the correct fix.
- **Plain-Postgres guarantee** — add a SQL-only transport test against stock Postgres asserting parameterized `query`/`execute`/`transaction` and error mapping all work when `isNucleus=false` (`features.ts:24`). Ensure no Nucleus-only SQL leaks into the SQL model path.
- **New test tier** `packages/neutron-nucleus/test/integration-docker.test.ts` using `testcontainers` (or a `docker compose` fixture) to run against **both** a real Postgres image and a real Nucleus image. Cover: feature detection, every model's round-trip, the comma-containing value regression (`kv.rpush('k','a,b'); expect(kv.lrange) === ['a,b']`), TTL, transactions, and error codes → RFC-7807.
- Gate the docker tier behind an env flag in CI so unit runs stay fast.

**Tests:** the regression above is the acceptance gate. Add a `RFC7807` shape assertion on every thrown `Nucleus*Error`.
**Acceptance:** comma values survive round-trip on real Nucleus AND real Postgres; the SQL surface passes identically on stock Postgres; CI has a `db-integration` job.

### Phase 6 — Streaming, edge, and image parity (closes the Astro/Next gap)
- **Suspense/await streaming** — `client/await.tsx` exists; wire it to the streaming renderer so `defer`-style loaders flush a shell then stream resolved data (out-of-order chunks with inline `<script>` data patches), matching Remix `defer`/Next Suspense.
- **Edge runtime hardening** — grow `runtime/edge.ts` (currently 19 LOC) into the documented edge surface; ensure the cloudflare `_worker.js` path uses `renderToReadableStream` and the default stack.
- **`prerender`/ISR for app routes** — add `export const prerender = true` and a revalidate window so app routes can be statically emitted (closes the rss.xml gap #13 generically: a GET-handler route with `prerender` writes its file at build).
- **`<Image>`/`<Picture>` density + AVIF defaults** — `client/image.tsx`/`picture.tsx` exist; add responsive `srcset` generation and AVIF-first defaults to match `next/image`/Astro `<Image>`.

**Tests:** streaming e2e asserts shell-before-data ordering; prerender test asserts `rss.xml` + a `prerender:true` app route emit files under the static adapter; image test asserts `srcset`/AVIF output.
**Acceptance:** a deferred loader streams; `rss.xml` is emitted by the static adapter; `<Image>` emits responsive AVIF/WebP.

### Phase 7 — Consolidation, docs, and contract test harness
- Single canonical examples in `apps/site`/`apps/playground` that use `createDefaultStack` + `/health` (so "every example wires it right").
- A cross-SDK conformance test (shared with Go/Python/Rust) that hits `/health`, asserts middleware order via response headers (e.g. `x-request-id` present, CORS applied), and RFC-7807 error shape.
- Update `FRAMEWORK_CONTRACT.md` references and remove `startServer`-runs-Vite from any docs.

**Acceptance:** the TS SDK passes the same conformance suite the other SDKs will run (ties into existing Task #50).

## 8. Scoring rationale
- Routing/render core: 7 (strong matcher + data flow, but path fragmentation).
- Islands/hydration: 5 (works, regex-fragile, two systems).
- Data/caching: 9 (genuinely excellent).
- Contract conformance: 3 (no /health, no enforced middleware order, no drain in prod entry).
- Type safety/DX: 6 (typed routes exist but off; `as any` at render).
- Nucleus client: 5 (comma bug, no real-DB tests).
- Tests: 7 (223 green, but DB is mocked, no e2e build-and-serve).

**Composite: 6.5 / 10.** Phases 1-3 alone move it to ~8.5; Phases 5-6 take it to a genuine 10.
