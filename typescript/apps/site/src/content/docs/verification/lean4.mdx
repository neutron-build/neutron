The `lean4/` directory contains machine-checked proofs of critical Nucleus algorithms using the Lean 4 proof assistant. These are hand-written Lean models of the algorithms — not machine-extracted from the production Rust — so they give mathematical guarantees that the modeled algorithm *designs* are correct, modulo a small set of explicit axioms.

## What's Verified

### MVCC (Multi-Version Concurrency Control)

- **Snapshot isolation** — Transactions see a consistent snapshot
- **No dirty reads** — Uncommitted writes are invisible
- **Visibility correctness** — Version chains resolve correctly

### Page Allocator

- **No double-free** — A freed page cannot be freed again
- **Conservation** — allocated + free = total (no page leaks)
- **Allocation validity** — Only free pages can be allocated

### Buffer Pool

- **Capacity bounds** — Pool never exceeds max size
- **Pin safety** — Pinned pages are never evicted
- **Eviction correctness** — Only unpinned pages are evictable

### Cryptographic Primitives

- **HMAC-SHA256** — Output length, determinism, PRF security
- **Constant-time comparison** — Timing-attack resistance (examines all bytes)
- **PKCE (RFC 7636)** — Roundtrip correctness, determinism, collision resistance

### Data Structures

- **LRU Cache** — Capacity bounds, set/get consistency, no duplicates
- **Bloom Filter** — No false negatives, insert monotonicity, bit array invariants
- **Sliding Window** — Non-negative estimates, accurate counting, rollover correctness

## How It Works

1. **Models** hand-mirror the Rust types and functions as Lean 4 equivalents (they are written and maintained by hand, not auto-generated from the Rust)
2. **Specs** state the properties to prove as Lean theorems
3. **Proofs** provide machine-checked evidence that the properties hold
4. Lean's type checker verifies every proof step; the only trusted inputs are the explicit `axiom` declarations the proofs build on

## Example: No False Negatives

```lean
theorem no_false_negatives (bf : BloomFilter) (item : List UInt8) :
    (bf.insert item).mayContain item = true
```

This theorem states: after inserting an item into a Bloom filter, `mayContain` always returns `true` for that item. It is proved in full in `Structures/` — the proof carries no `sorry`.

## Status

The suite is 26 files and 70 theorems with **zero uses of `sorry`** — every stated theorem has a complete, machine-checked proof. Those proofs rest on 28 explicit `axiom` declarations that state foundational assumptions (some load-bearing); the results hold modulo those axioms.

These are hand-written Lean models of the algorithms, not machine-extracted from the production Rust. They establish that the algorithm *designs* are correct — they do not, on their own, certify that the shipped Nucleus binary is formally verified. The Rust implementation is validated separately by its test, property, and differential-fuzzing suites.
