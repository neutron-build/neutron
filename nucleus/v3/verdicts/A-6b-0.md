### R1. ESCALATE 1: after a failure, each task keeps its own clock (the pre-gate's option B)

**Decision.** After the world fails, `sleep(d)` advances only the calling task's own clock; the world's clock stays where the failure left it. Rejected: option A (`now` and the failed-world `sleep` through `Sched::acquire`'s unwind turn) is also deterministic, but it makes the infallible `now` block until every lower task has finished, adding a hang path, and it lets the post-crash unwinding of dead tasks set the next life's clock; option C (declare the race) narrows S-DET by hand. B keeps A-1b-F1 (b)'s purpose ("so time-bounded loops end") and restores what the Base had for every later life: the inherited clock is the clock at the failure.

**Why it is sound.** Before the failure only the baton holder runs, and a successful `sleep` adds `d` before its task's next yield, so the world's clock at the failure is a function of the seed. After it, a task's own offset depends only on its own calls. No task reads another's offset, so OS order cannot reach any value. The prototype (above) shows one clock and one sleep-count vector per shape.

**Card amendment (exact text).**
- Limit 3, replace "`SimEnv::sleep` (Work 2)," with: "`SimEnv::sleep` and `SimEnv::now` (Work 2), one per-task post-failure clock offset (Work 2: a thread-local beside `TASK`, set to 0 where `run_life` sets `TASK`, or a `SimWorld` field indexed by task id),"
- Work 2, replace its first paragraph (from "**A-1b-F1 (b): `sleep` in a failed world.**" to the end of the quoted S-ENV sentence) with:
  "**A-1b-F1 (b): `sleep` in a failed world.** In `SimEnv::sleep`, when the task's yield fails because the world failed (it crashed, deadlocked or livelocked), `sleep` adds `d` (saturating) to the calling task's own post-failure offset, and returns; it does not change the world's clock. `SimEnv::now`, on a task thread, answers the world's clock plus the calling task's offset, which is 0 until that task's first `sleep` in a failed world. The offset belongs to one task in one life: no other task reads it and the next life starts without it, so the clock `run_life` carries into the next life is the world's clock, which stops at the failure. A successful `sleep` is unchanged. A call from a thread that is not a task still returns at once, advancing nothing, and records a halt (Work 6); `now` there answers the world's clock. A yield refused with `SimFail::Baton` (the thread already holds the world) still returns at once, advancing nothing. S-ENV doc, "Clock and randomness" bullet, add: "A task observes a crash only through a fallible call. `now` and `sleep` keep working in a failed world: each `sleep` there advances the calling task's own clock by its `d`, so a time-bounded loop ends after a crash, while the world's clock stays where the failure left it, so one task's unwinding never moves another task's time or the next life's (A-1b-F1 (b); S-DET)."
