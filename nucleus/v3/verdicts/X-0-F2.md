## Findings

Scope ok (tree.rs, pool.rs, tests/faults.rs only; X-0-F3's `check()` and the
`test-hooks` gate untouched). No unsafe, no non-test unwrap/expect/panic, and
pub(crate) items are documented. The atomicity logic is sound: every reachable
`new_page` now happens before the leaf's first mutation; the reservation count
(leaf, plus one per retained ancestor, plus root when `path.first()` or the leaf
is the root) is exact under T-COUPLING; parents are dirtied before mutation;
`locate` resets the frame on a failed read. Every fault-injected run passes
`check()`, the model comparison and reopen. Workload height is 4, and at least
two root splits happen under fault. No `Corrupt` surfaced, so nothing is
escalated.

1. **Blocking: the reservation leaks store pages without bound.** Every insert
   into a leaf that fails `page::is_safe` reserves `1 + |path| (+1)` pages.
   Because `MAX_LEAF_COST` is about half a page, that covers most inserts once
   leaves are past half full, and most of those inserts never split. The unused
   pages go back to the pool, but their store ids are never reused
   (`release_new`, `PageStore::free` is a no-op). Measured with 50,000 random
   inserts, 16-byte keys, a 256-frame pool and MemStore:

   | Values | Reachable pages | Allocated at the tip | Allocated at the scaffold |
   |---|---|---|---|
   | 100 B | 1,146 | **160,109** | 1,146 |
   | 16 B | 374 | **138,844** | 374 |

   That is 140–370× growth: about 1.3 GB of MemStore RAM for a 9 MB tree, and
   file ids or sparse-file size growing the same way. Each reservation also
   evicts up to h+1 resident pages, dirty write-backs included, which churns
   the cache in E0's constrained bench mode (`e0-bench`, 100-byte values).
   The card asks to "release unused ones afterwards". The doc claim "exactly
   like a deleted leaf's (T-NOMERGE)" is wrong, because T-NOMERGE leaves stay
   reachable.

   **Rework**, within the Touch list:
   - (a) Recycle released, never-published ids in the pool's free/unpin path
     (pool.rs): `new_page` takes a recycled id before calling `store.allocate`.
   - And/or (b) reserve only when the insert will really split: test the fit on
     an owned copy of the leaf, or compute the post-remove fit before mutating
     (tree.rs).
   - Add an assertion to faults.rs: allocated store pages ≤ reachable pages +
     a small bound, after the unfaulted workload and after a long
     small-value run.

2. Non-blocking: DIRTY-AFTER is now an equivalent mutant (see the table). The
   design removes the window the card wanted it to probe, so it cannot be
   caught.

3. Non-blocking: `faults_pool_starved_mid_split` shrinks the pool instead of
   "holding pins from the test". The deviation is documented and sufficient,
   since with pre-allocation every starvation happens before the first
   mutation.
