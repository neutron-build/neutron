## Findings

Scope ok: the card diff (`nucleus/v3-scaffold...HEAD`) touches only
tree.rs, pool.rs, tests/faults.rs, plus the round-1 verdict file. `check()`,
`victim`, the page format and the test-hooks gate are untouched. No unsafe,
no non-test unwrap/expect/panic, and new items are documented.

1. **The leak is fixed.** The worker did both (a) and (b). `release_new`
   unmaps the id under the table mutex and pushes it onto a recycle list;
   `new_page` pops from it, under the same mutex, before calling
   `store.allocate`. `leaf_insert_step` reserves only when an owned copy
   of the leaf, run through the same `leaf_remove`/`leaf_insert`, refuses
   the cell. Re-measured with a throwaway test (since deleted): 50k random
   16-byte keys plus 5k growing upserts, MemStore with 8 KiB pages. Excess
   allocated over reachable, against roughly 160k in round 1:

   | Values | Frames | Reachable | Allocated |
   |---|---|---|---|
   | 100 B | 256 | 1,178 | 1,181 |
   | 16 B | 256 | 415 | 418 |
   | 16 B | 16 | 422 | 425 |
   | 100 B | 16 | 1,160 | 1,161 |

   G2-ROUND1 reproduced 160–175k on the same harness. The bound in
   faults.rs, `reachable + height + 8`, holds up when re-derived. Every
   reservation that happens consumes at least one page, so the recycle
   list never grows past the largest single reservation minus one, which
   is at most h + 1. A faulted run can strand at most one id: the id a
   failed `new_page` had already popped or allocated. The oracle is
   checked on every faulted sweep run as well as on the long small-value
   run, and either removing recycling or restoring the round-1 code fails
   it.
2. **Round-1 soundness is preserved.** The sweeps still assert that every
   failed op leaves the model unchanged, run `check()`, compare the full
   range with the model, and reopen after every injected fault, and they
   still require height ≥ 3. A recycled id is never published and is never
   resident when it is handed out. The lock order is table → recycled.
   The fit test cannot disagree with the real path because it runs the
   same routines, and a disagreement would surface as `Corrupt`, not as
   silent damage. No `Corrupt` appeared in any unmutated run, so nothing
   is escalated.
3. Non-blocking: if `new_page` fails after it has popped a recycled id,
   that id is dropped. This leaks one id per failed `new_page`, the same
   as round 1 did for a freshly allocated id.
4. Non-blocking: the fit test copies a full page for each insert into an
   unsafe leaf. That trades a memcpy for avoided reservation churn, which
   is worth noting for E0 bench numbers.
5. Non-blocking, carried from round 1: DIRTY-AFTER is an equivalent
   mutant, and `faults_pool_starved_mid_split` shrinks the pool instead of
   holding pins.
