## Findings
- **The matcher semantics match the installed binary.** I read the
  ~/.opencode/bin/opencode v2.0.32 strings myself:
  - `rb` escapes the pattern, maps `*` to `.*` and `?` to `.`, makes a trailing
    ` .*` optional, anchors `^...$` with the `s` flag, and replaces `\` with `/`
    on both sides.
  - `UC` is `findLast` over action+resource, with "ask" as the default.
  - `wL` takes every tree-sitter `command` descendant as its own resource, and
    uses the parent's text when that parent is a `redirected_statement`.
  - `Nw` = cd/chdir/popd/pushd (plus PowerShell forms). Those commands go to the
    directory check, not to the bash rules.
  - The portable scanner `kL` is used only under
    `experimental.portable_shell_scanner` or the local/dev channels, so release
    builds use tree-sitter.
  - The probe log agrees: -C reset, cd && reset and --amend were all "Permission
    denied: shell", and git status --porcelain completed.
- **bash_permission is close to opencode, but not exact.** It cuts heredoc
  bodies into separate commands, which tree-sitter does not do, so the model can
  deny where opencode allows. This affects tests only; the runner never calls
  the model.

  most likely one in practice is `git --no-pager ...` / `git -P`, which
