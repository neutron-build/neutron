# Findings

1. **(follow-up B-0-F6-F1)** `unit_stop` discards the stop call's exit status and *all* of its output, not just the expected not-loaded message. For the expected case this is exactly what the card wants, and a not-loaded unit is indistinguishable from noise. But a genuine stop failure on a *loaded* unit (systemd stop job fails) previously printed its reason to the console; now nothing prints it. The 60-second disappearance poll bounds the wait but surfaces nothing, and the only indirect signal is the *next* `unit_start` on the same unit name failing (with the pre-existing empty `stderr_tail` from `unit_start`, so even that error is close to silent). Non-blocking because the case is rare and still fails loudly enough to stop the run, but the reason should be kept.
2. `podman::stderr_tail` duplicates the truncation logic of the private `tail()` helper instead of calling it. Pre-existing shape, now load-bearing for the fallback: my TRUNC-HEAD mutant on `tail()` was invisible to every fallback test (only `tail_keeps_the_end_and_cuts_on_char_boundary` caught it); the same head-mutant on `stderr_tail` (TRUNC-HEAD2) is caught. A future unification would close this two-seam trap.
3. Minor: `failure_message_tail` `fs::read`s the whole NB_LOG before tailing 4000 bytes — error path only, but qdrant init logs can be large; a bounded tail read would avoid the spike. Not worth a card on its own.

# Follow-ups

**B-0-F6-F1 — surface real `unit_stop` failures.** In `podman::unit_stop`, capture the `systemctl --user stop` exit status and output instead of discarding them unconditionally. When the exit status is non-zero and the message is *not* the expected "Unit … not loaded." pattern (or the unit is still active after the bounded poll), report it — e.g. an eprintln to the harness console or an anomaly on the row — so a genuine stop failure keeps its reason after B-0-F6's silencing. Optionally also stop hardcoding `stderr_tail: String::new()` in `unit_start`'s error so the follow-on start failure can carry output too.
