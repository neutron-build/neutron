## Rulings on the author's choices

1. **Dropping R-1-caps-chunk-records: accepted.** One `Put` is one op in one record. Splitting it would need a continuation op, which means a WAL-format change (A-6a) and new supersede semantics. The bound `max(chunk_batch, largest record) ≤ wal_seg_size/4` stays finite and is stated. B-1d should still measure the small-commit stall behind one near-maximal record.
2. **§14.1 lock mode (exclude writers, fail rather than wait, sharing among read-only opens left open): accepted.** Excluding writers is forced, because §13 step 6 recycles segments and slots. Failing rather than waiting matches N11's exclusive-lock model. Sharing is safe either way, because no reader writes. This also maps onto OPFS's `read-only` and `readwrite` access-handle modes. Condition: the lock itself must write nothing (R3).
3. **The pool minimum applying to the evictable part: accepted.** Dirty frames are effectively pinned in a read-only open, so only `F − dirty` frames can serve §5.4's latch path. Requiring the minimum both during pass 2 and after it is right. Counting `R_EPOCH` is conservative, since no checkpoint runs. `R_MAP` still covers the MapLeaf pins of dirty frames.

## Rework items

- **R1 (must, §14.1 + I-RO-OPEN row).**
  - State that a read-only open of a store that stopped on 53100 (poison is in-memory, §9.2, so the file is a crashed store) succeeds with **zero free bytes** and writes nothing, so the data stays readable and exportable, provided the open's pool meets the evictable minimum for the replay.
  - Name an A-7d test, e.g. `t_ro_open_disk_full` (or a named case of `t_ro_open`):
    - SimEnv stops a writer with ENOSPC at each write point: WAL append, segment creation and preallocation, file extension (§4.5), a checkpoint page write, and the meta write;
    - a read-only open then runs with a SimEnv that reports zero free bytes and refuses every write;
    - the open must succeed, its reads must equal a read-write open of a copy on a roomy Env, a full scan of every published tree must succeed, and the files must be byte-identical after close.
- **R2 (must, §14.1 "The remedy").** On a full volume, a read-write open can fail with 53100 at its boot checkpoint. So the 53200 remedy must include a read-only open with a larger pool budget (`F` is set per open from N16, §5.1), and the text must say that this is the only remedy when there is no free space. The test in R1 covers both: 53200 with nothing written, then a larger-budget read-only open that succeeds at zero free bytes.
- **R3 (must, §14.1 "No writer").** N11's lock must create or write no file: an advisory lock, or the OPFS access-handle mode, through `Env`. Otherwise a lock file breaks both "writes nothing" and the zero-free-bytes case.
- **R4 (must, §12.5 one sentence; the orchestrator amends the card's Limits).** A segment file shorter than its position needs, from a 53100 during preallocation, ends the valid end at its EOF. It is a stop, not a 58030, for both opens. R1's segment-creation stop point needs this to be decidable.
- **R5 (precision, §11.4, in Limits).**
  - `t_chunk_queue_bound`'s gauge is kept at the WAL queue's append and sync site, keyed by the record's `txn`. It is not a tally kept by the large txn's batcher (the C4 decision 1 principle: an independent counter).
  - Op sizes must not divide `chunk_batch`, and the large op must follow small ops in the same materialisation. Without both, BATCH-PLUS-ONE survives.
