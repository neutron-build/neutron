## Findings

1. **The scenarios isolate the count rule.** G5 (nucleus/v3/zz/x.txt) and G5U
   (nucleus/v3/é.txt) each add one extra file to the verdict commit. Both are
   inside nucleus/v3 and match no CORE_PATHS entry (docs/, scripts/, tools/,
   root CORE_PATHS/Cargo.toml/deny.toml/clippy.toml/rust-toolchain.toml,
   crates/nucleus-store|env/), not verdicts/ or docs/, and the verdict's
   Commit is the work commit (= tip^). So every rule but the tip check passes.
   Because diff-tree emits paths in byte order, "verdicts/" (0x76) comes
   before "zz/" (0x7A) and before "é" (UTF-8 0xC3 0xA9), so the verdict is
   tipfiles[0] and only the `-eq 1` count can refuse the merge. TIP-COUNT fails
   exactly G5 and G5U; the other 76 scenarios still pass.
2. **The premise checks are sound and have teeth.** tip_first reads the -z
   diff-tree with NUL translated to newline (no C-quoting of é). It checks the
   same ordering enforce-lib relies on. Two mutants of the test itself move
   the extra file before the verdict (aa/, _.txt), and each premise fails. If
   a later edit breaks the "sorts after" assumption, the suite reports it
   instead of passing for the wrong reason.
3. **Card mutant reproduced:** the 78 scenarios on a /tmp copy fail only G5 and
   G5U. A realistic "read only the first path" bug (TIP-FIRSTONLY) is also
   caught by exactly these two.
4. **Pre-existing gap (not this diff): the Commit field accepts any revision
   expression.** check_merge resolves Commit with `git rev-parse
   "$vcommit^{commit}"`. A verdict whose Commit is `card/v3-<ID>~1` always
   equals tip^. I ran a /tmp probe: verdict with Commit card/v3-G6~1, then a
   late spikes change, then the verdict re-committed with a new Date. It
   merged ("G6 merged into scratch/pass1"). This defeats the G4 protection. It
   also explains why TIP-NOFIRST survives: with a hex Commit, the
   "first file is the verdict" test is implied by Commit = tip^, so no
   scenario can isolate it. This card is test-only and may not change
   enforce-lib semantics, so the fix is a follow-up.
