## Findings

1. **The latch and the sync layer are right against S-STORE §5.3 and the card's R0-R4, W1-W7 and F1-F7** (read in full). `admits` is R1 (a)∧(b)∧(c) exactly: neither a shared request nor any try passes a queued exclusive, and the head's count is the queue's maximum. A queued exclusive leaves the queue only at its own re-check, so no try can succeed at the release instant. A release grants nothing, and it notifies all whenever any request stays queued. Every arrival decision and every queue decision runs under one hold. An overflow returns `Invalid` before any tick and changes nothing. At most one batch is outstanding: a new head batch needs `Free`, or a shared head beside shared holders, and neither can occur while handed members are uncollected. A waiter holds only the internal mutex's wait. After construction nothing allocates on an `Ok` path. Poisoning maps to `Poisoned` in `mutex_lock`, `condvar_wait` and both cell tries, on both backends. Every seq difference wraps, and every access is `get`/`get_mut`. No `unsafe`, no `cfg`, and no non-test unwrap, expect or panic.
2. **The production fix (574da08a) is right.** std's `compare_exchange` returns the value it compared in `Err`, so the reload answered a possibly later value and disagreed with the model backend. No test can tell the two apart: T-RELOAD passes both atomic tests, and must, on one thread. It is accepted by reading.
3. **W4's notify after a batch grant is redundant as the latch stands (G6, uncaught everywhere).** A queued member can be asleep only after a refused re-check. A refusal can turn into a grantable head batch only through a release, and a release notifies all while a request is queued. So every batch member is already awake when a batch is granted. The code is harmless and keeps the card's rule. It becomes load-bearing as soon as a waiter can leave the queue without a release (A-4c's withdrawal transition). F2 says so.
4. **`latch_forced_batch` is a sound pin, and it pins W2's tick count one way only.** The order it forces, three readers queued behind the exclusive holder, is reached through an observable condition read under the latch's own mutex (`info().waiting`), never through timing. Once that holds, the batch, its stamps and the monitor's verdict are the same under every order in which the OS runs the re-checks. With three readers, at least one handed member has a non-zero offset. So its catches are assertions in every run (one-tick and holders-one confirmed). Its poll is a `yield_now` loop bounded by a count. That breaks the letter of Limit 6's "Every wait is a condition wait", but it is no timing dependence, and the public API has no condition to wait on. Accepted, with the card text in F3. An over-ticking batch passes: the test never checks the release stamps (F4).
