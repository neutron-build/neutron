## Findings
- **R1/R2 semantics: correct against the card.** The snapshot covers the
  shared ref store and drops refs/stash. Created, moved and deleted refs are
  all compared. The card branch is skipped. W = `rev-list <branch> ^pre_head`
  is listed even when nothing moved, so a bad pre_head fails closed. R2's
  nucleus/* rule allows creation, refuses deletion and refuses non-ff moves.
  Every git failure becomes one entry; exit 1 of `merge-base --is-ancestor`
  is the only accepted non-zero.
- **Snapshot lifecycle: correct.** The snapshot is taken once, right after
  pre_head; a failure `sys.exit`s before the ledger start record and before
  any attempt. The check runs after every attempt, before stray/scope, and
  breaks on violations. The final check feeds `result["scope"]` and RUNLOG.
  The `finally` at-exit check covers quota, disk, exception and SIGINT/SIGTERM
  (signals are ignored there). It is untested; see F1.
- **Restore printing: correct, never run.** I checked the three printed forms
  in a scratch repo. All three are compare-and-swap: `update-ref R old new`,
  `-d R new`, and `R old 000…` (zero oid sized to the hash, so SHA-256 works).
  Each fails rather than clobbering a concurrent update.
- **Env-var denial: complete for the card's list.** GIT_DIR=, GIT_WORK_TREE=,
  GIT_COMMON_DIR= and GIT_CONFIG* each get the "", "* " and "*/" prefixes.
  `export GIT_DIR` is named as a residual.
- **Residual not named (design, F2).** The Goal's own example,
  `GIT_DIR=<root>/.git git commit`, commits onto the root checkout's branch
  (nucleus/v3-scaffold). That commit is not in W, and it is a fast-forward, so
  it passes both R1 and R2. Only the bash-layer denial and `stray_commits`'
  card-name match stand in its way. The comment's claim ("every write of a ref
  that carries this run's commits or is protected") is literally true, but this
  case is not listed among the residuals.

  function-level RF1..RF10 (the card calls them E-RF*).
