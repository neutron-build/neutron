### Round-1 REWORK items

1. **Concurrent `gc()` lost writes: closed.** Each `gc()` call now takes
   a fresh lock-table identity from `next_txn` (the "fresh TxnId" fix
   option), so concurrent gc calls exclude each other through L-EXCL.
   One call's `release_all` frees only keys that call holds. The id never
   collides with a txn or with the lock table's reserved owner word. gc
   acquires with NoWait and holds at most one key, so it can neither be
   part of a deadlock cycle nor reach the escalation budget. Under the
   lock, the re-check is sound: C-COMMIT-ORDER releases a writer's lock
   only after apply and `mark_applied`, so a re-read under the lock sees
   any replacing value.

   **Gate probe (independent of `gc_race.rs`).** Writers use RR
   (retrying on Serialization), 8 keys per writer, and phased
   delete-all/put-all rounds. Each read-back retries for 100 ms, and a
   final durability check runs after 5 more `gc()` calls. Configs: 2 gc
   threads + 4 writers, 3 gc + 6 writers, and 2 gc + 4 writers with a
   4096-byte undo budget (spilling), plus a 0-gc control.
   - Round-1 code (FIXED-GC-ID): committed puts were lost in 9/9 gc runs,
     21–62 lost per run.
   - HEAD: 0 lost in 9/9 gc runs (about 120k–180k puts and 80k–200k
     `gc()` calls each). The controls were clean.

2. **The GC lock and re-check now have a test.** `tests/gc_race.rs`

### Observation (outside X-3's scope; for the orchestrator)

- In the shared `commit_with`, `mark_applied` can return with
  `visible_ts < c` while a lower ts is still pending. A session's next
  txn then may not see its own just-returned commit: about 15–40% of
  immediate read-backs in the probe, including the 0-gc control. For
  the same reason an RR put right after the session's own committed
  delete can fail with Serialization.
- This is X-1a common-component behaviour (C-T0's commit-visibility
  window), not an arm-(c) defect. However, the doc comment in
  `gc_race.rs` saying "Correct code needs one read" is inaccurate; its
  retry loop already handles it.
- Worth confirming in S-2 whether read-your-own-commit is a required
  session guarantee.
