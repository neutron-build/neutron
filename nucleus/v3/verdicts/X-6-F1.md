## Follow-ups

X-6-F1-F1 (runner, core): pre_head is per run, so a forged
"nucleus v3: <ID> verdict ..." commit from an earlier run is exempt on a
`--keep` rerun. Persist a trust anchor, or scope-check on every exit path, and

X-6-F1-F2 (runner, core, pre-existing): `git update-index
--assume-unchanged/--skip-worktree` hides uncommitted edits from the runner,
including edits to verdicts/<ID>.md. Refuse such entries (`git ls-files -v`),
or run acceptance from a clean export of HEAD.

X-6-F1-F3 (runner, core, pre-existing): the opencode bash deny list matches
prefixes and misses history rewrites (`git rebase`, `commit --amend`,
`update-ref`, `switch -C`, `restore`, `git -C . reset`, `git -c k=v checkout`).
Deny them and state the amend/rebase rule in WORKER-PROMPT.

X-6-F1-F4 (runner + enforcement scripts, core, pre-existing): replace refs
(and grafts) rewrite what every git call in run_card.py sees, which hides
arbitrary committed changes, protected paths included, from scope_violations.
refs/replace is shared by all worktrees, so it also reaches the main checkout,
merge-card.sh and audit-merges.sh. Run the runner's and the scripts' git calls
with `GIT_NO_REPLACE_OBJECTS=1`, or refuse when `refs/replace/` or
`info/grafts` exists. Deny `git replace` to workers.

X-6-F1-F5 (runner tests, core): add a scenario where a non-verdict commit sits
between the gate's verdict commit and pre_head, with the verdict untouched, and
expect no violation. This catches LOG-NO-PATH (dropping `-- f` from
gate_committed's log), which today survives. That mutant would report a false
"(protected)" on a valid verdict, the X-6 N1 symptom.
