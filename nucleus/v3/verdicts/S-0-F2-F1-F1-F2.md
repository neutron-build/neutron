## Rulings on the implementer's judgment calls

1. **The reason pin is sound. No re-scope.** Since S-0-F2-F1-F1-F1, the hex
   branch refuses anything that is not a text prefix of tip^'s full lowercase id
   (`[[ $parent != "$vcommit"* ]]`, case-sensitive, glob chars quoted). No value
   with an uppercase letter or a non-hex suffix can be such a prefix. So
   END-ANCHOR-DROPPED and UPPERCASE-OK do not change accept/refuse on any
   input. They change only which rule refuses and what the operator is told,
   which makes them equivalent mutants at the verdict level. The card's
   "only the end anchor can refuse it" is stale for that reason. The only
   observable left is the reason, and pinning it is the right test. G7C already
   set the precedent ("G7C's refusal names the ambiguity").
   `hexrule_refusal` requires a non-zero exit as well as the message, and it
   greps only the stable leading clause
   `verdict Commit '<value>' is not a hex commit id`, not the parenthetical. So
   rewording the hint does not break it. Rewording the clause does, and that is
   intended: OWN-HEXCHECK-GONE shows these two pins are the only tests in the
   suite that notice the hex rule is missing. The plain "is refused" assertions
   are still worth keeping, because they catch the realistic variants that
   actually merge (OWN-NORMALIZE, OWN-REMATCH). Card Work 3 ("fail ONLY under
   its respective mutant") holds: each named mutant fails exactly one check, in
   its own scenario.
2. **The G6U loop is deterministic enough, and its premise is adequate.**
   Commit dates are not pinned, so the ids vary between runs. A 7-digit id has
   no a-f with probability (10/16)^7 ≈ 3.7%, so 64 misses in a row has
   probability ≈ 10^-91. If the loop ever runs out, it fails loudly: the
   premise asserts a letter in `${g6u:0:7}` and that the value resolves to tip^,
   so the scenario cannot pass vacuously. The letter must be in the first seven
   digits, and the comment says why: an all-digit prefix has no uppercase form,
   and under a dropped anchor the unanchored match reads only seven digits. That
   is what keeps G6U silent under END-ANCHOR-DROPPED, and the mutant run
   confirmed it. G6E needs no such guard, because `~` fails the class whatever
   the digits are.
