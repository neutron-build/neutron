## Why REWORK

**R-1 (blocking): §9's skip at `S` loses coverage.** §9.1 step 5 skips every row whose live version has ts `= S`. §9.4 and §9.6 then claim the writer at `S` "wrote `E@S` itself through maintenance". That is false for an UPDATE that leaves the entry unchanged. §8 keeps v2 §6's maintenance verbatim, and v2's `maintain_update` (`nucleus-catalog/src/index.rs` at 2e4776fb, "An unchanged entry is left alone (no tombstone, no new version)") writes nothing in that case.

Counter-example:
1. Row `r` predates the index, so it has no `E`.
2. After the fence, a WriteOnly-aware txn commits at `u` with an UPDATE of a non-indexed column of `r`. Its maintenance writes nothing.
3. T3 takes `S = visible_ts = u`. The scan skips `r` because its version is at `S`.
4. The index is published without `E`, and I-IDX / I-BUILD-COVER fail.

This is likely under any write load, because `visible_ts` is usually the latest commit's ts.

**Suggested fix:** load at `S := f`, the fence's own commit ts.
- **Registration.** `register_at(f)` is admitted: `W ≤ R < f ≤ visible_ts` once T2 has acked. That satisfies S-STORE §10.1's "S > R".
- **Why nothing collides at `f`.** T2 writes only `cat_idx`. No relation version and no logged index entry can be at `f`, so nothing is skipped. I-LOAD-DISJOINT becomes trivial, N5 retires, and the leftover argument of §9.5 holds with `S_old = f_old`.
- **Coverage.** Versions `< f` are covered by the load. Versions `> f` are covered by the fence argument.
- **One rule to state.** T2 must take a ts. It rewrites the IdxRow, so it is not a `Released(⊥)` commit (C-T0 v8.1 §3.1 step 0), and the spec should say so.

**R-2: the §3.2 era maintenance omits a code rule.** v2's `set_not_null` keeps `since` on a column that is already NOT NULL (the `(true, true)` arm in `schema.rs`; `ddl.rs` says "a SET on an already-constrained column keeps its original era"). §3.2 says only that SET NOT NULL sets the new version. A worker following it would make a redundant SET NOT NULL silence XX001 for stray NULLs in rows between the two eras. Fix: state the rule, add a mutant (for example SET-REARMS-CONSTRAINED), and add a pin. The author's other claims about the stale doc hold:
- v2's file at 2e4776fb still states `v == V`;
- 180f9503 is an ancestor of 2e4776fb;
- the decode rule `not_null ∧ v ≥ since`, the flags bit4 word, its elision, the three rejections and DROP NOT NULL → 0 all match the code.

**R-3: I-OP-BOUND does not bound catalog ops.** A RelRow def carries the `missing` fast-default bytes inline, with no size cap. So `ADD COLUMN … DEFAULT <large constant>`, or many such columns, yields a `cat_rel` Put larger than `wal_seg_size / 4`. Fix: cap the encoded def at `ROW_LIMIT` (54000), or toast `missing`. Then extend I-OP-BOUND and its test.

**R-4: DROP-SPLIT-COMMIT is masked.** If the row delete commits first and the process crashes, the tree is no longer named by any catalog row. It is live and its id is `< H_boot`, so §5.3's orphan job drops it at reopen. "Nothing leaks" therefore passes under the mutant. Fix: make `t_drop_commit_atomic` assert before the boot jobs run (or with the orphan job disabled), or drop the mutant and the claim that one record is needed for leak-freedom.

**R-5: drift from C-T0 draft 8.1.** C-T0 8.1 was merged at 5ff1bd06, after S-3's base 2b3924de.
- **Boot id.** "epoch" and I-EPOCH are now the boot id and I-BOOT-ID (§4.2's toast id, §1).
- **Snapshot registry.** "registry mutex" is now the snapshot registry, distinct from the live-txn registry (§9.1 step 3).
- **Lock order.** The per-counter mutex is absent from C-T0 v8.1 §2.6's lock order. §6 should place it there: callers hold lock-table entries (logically) when they call `alloc()`, and the mutex sits above the reservation's lock-table entry, wait, stripe, gate and latches, and above every short mutex. Add it to the §13.2 notes.

**Smaller items, to fix in the same rework:**
- **R-6.** §4.4's "never wait" is false inside a foreign escalated run (C-T0 §6.2: foreign acquires inside a run wait). Qualify it.
- **R-7.** §4.3 and N4: row entries may be chains of up to `ROW_LIMIT` (128 pages at 8 KiB, 256 at 4 KiB), not `toast_chunk`. A-5 must measure the chain free at `ROW_LIMIT`.
- **R-8.** §2.2's "index entries are always inline" assumes `V_INLINE ≥` the longest row key, which A-2's formula does not guarantee. Reword it, or require that bound in N-notes.
- **R-9.** Name I-IDX's mutants, and state RESUME-OLD-S's observable (72000 at registration, or a pruned scan only if the check is bypassed).
- **R-10.** §7.3 says CreateTree is "logged in the commit". For a large txn it goes in a chunk (§5.3). §5.3's abort text covers only the large-txn continuation: a small txn's abort must also drop its created trees.
- **R-11.** The orphan job must read its catalog snapshot before it lists the directory, and skip `dropping` trees, or it races drop cleanup.
