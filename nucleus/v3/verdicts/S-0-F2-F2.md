## Follow-ups

**S-0-F2-F2-F1: fail closed in the remaining git listings (audit-merges
rev-list, runner stray_commits).** audit-merges.sh reads
`git rev-list --first-parent "$ref" -- ...` through `done < <(...)`, so a
failed rev-list is read as no commits: confirmed, `audit-merges.sh no-such-ref`
prints "audit: ok (0 commits)" and exits 0. That script is the CI backstop
for everything that bypasses merge-card.sh. Capture the list to a file and
refuse on a non-zero exit, with a bogus-ref scenario and a control. In the
same card, make run_card.py's stray_commits check git log's rc and treat a
failure as stray commits (stop the run). Today it fails closed only by
accident, because run() folds stderr into the output and git's "unknown
revision 'card/v3-<ID>'" line happens to contain the card id; any other
failure returns []. Both files are protected, so Opus implements it, and a
separate P session gates it.
