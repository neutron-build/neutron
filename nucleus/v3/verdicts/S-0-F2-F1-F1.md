## Findings

1. Correct to the card. The match is `[[ $vcommit =~ ^[0123456789abcdef]{7,40}$ ]]`.
   It is anchored at both ends, the class is spelled out (no locale range), and
   the value is not normalised beyond `vfield`'s trim. `vfield` takes
   `head -1`, so `$` cannot be satisfied before an embedded newline. The check
   runs before any `rev-parse`. A mismatch adds exactly one error and skips
   resolution. A match keeps the original resolve-and-compare unchanged, so both
   rules hold (HEX-REPLACES-CMP is caught by G4).
2. The premises are sound. `commit_is_tip_parent` reads the Commit from the
   committed tip verdict (`git show card/v3-ID:...`), not from the worktree. It
   compares that value against `card/v3-ID^`, and PREMISE-G6 shows it has teeth.
   COMMIT-SYMBOLIC proves that the hex rule alone refuses G6 and G6Z: with the
   rule removed, both merge.
3. The G2 reason pin is not vacuous. It requires a non-zero exit and the literal
   prefix of the tip-rule message, and that string has no other source in
   merge-card.sh or enforce-lib.sh. TIP-NOFIRST and TIPMSG-REWORD both make it
   fail.
4. Non-blocking: a short hex Commit can still name a ref. git resolves refs
   before abbreviated object ids. In a probe, with a branch named `0007c48`
   (A's 7-hex prefix) pointing at B, `git rev-parse -q --verify 0007c48^{commit}`
   returned B. A full 40-hex id still wins over a same-named ref. So a ref named
   with 7-39 hex digits restores the branch-following "symbolic Commit" the card
   closes. This needs a deliberately created hex-named ref, so it is unlikely by
   accident. The card required keeping `rev-parse` unchanged, so it is a
   follow-up, not rework.
5. Non-blocking coverage gap: no scenario pins the end anchor or the lowercase
   rule, although the card's Do-not refuses `<hex>~0`, `<hex>^`, `<hex>@{..}`
   and uppercase. END-ANCHOR-DROPPED and UPPERCASE-OK survive. The end anchor
   matters beyond `~0`: without it, a ref whose name starts with 7 hex digits
   (`deadbee-x~1`) passes the check and follows its branch.

## Follow-ups

- **S-0-F2-F1-F1-F1: resolve a hex Commit as an object, never as a ref.**
  `check_merge` resolves a hex `Commit:` with `rev-parse`, which prefers a
  same-named ref (refs/heads, refs/tags, refs/remotes, refs/<name>) over an
  abbreviated object id. A ref named `abcdef1` therefore makes the field
  symbolic again. Compare without ref lookup: for example, require tip^'s full
  id (`git rev-parse "$head^"`) to start with `$vcommit`, or refuse when
  `git show-ref` / `git for-each-ref` finds a ref of that name. Keep both the
  hex rule and Commit = tip^. Add a scenario: a branch named with the reviewed
  commit's 7-hex prefix, moved to point at a late change, must be refused. Add a premise that `rev-parse` of that name resolves to tip^. Add
  a mutant that restores plain `rev-parse` and is caught by that scenario. Class:
  core, Gate: P (enforce-lib.sh, test-enforcement.sh).
