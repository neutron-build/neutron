## REWORK items (fix in this stage)

Items 1–3 can hide failures. Items 1, 2 and 6 are in `src/sim/`, which
X-5b may change only for S-BATON and history queries (X-5b Touch rule 3).
So they cannot be deferred to X-5b. Each fix needs a new pinned test.

1. **Taint misses reads that start inside an issued range.**
   `Inode::taint_of` (`src/sim/disk.rs`) walks `issued.range(off..end)`,
   which skips an interval that starts before `off`. Gate probe: write
   8 KiB at 0 and sync, write 8 KiB again (it is dropped), crash. Reading
   `[0, 8192)` is tainted; reading `[4096, 8192)` is **not**. Every WAL
   read that begins mid-batch is affected, and so is `range_tainted`.
   O-3 (a) is blind there.
2. **The accept hook only matches an exact `(off, len)` read.**
   `SimDisk::accepted` reports served corruption only if some read had
   exactly the accepted offset and length. The WAL reader shape (read
   16 KiB, accept one record inside it) can therefore never be served.
   Gate probe: a tainted read of `[0, 8192)` followed by `accepted(f, 0,
   100)` gives `served = 0`. The hook also scans *all* earlier reads, not
   the most recent covering one, though its doc says "most recent". Card
   1.4 requires "an accepted range that was tainted at read time". So
   judge the accepted sub-range against the most recent read that covers
   it.
3. **The model lets a bulk load override newer writes.** `Model::scan`
   applies load entries after all commit ops. A Put or Delete at
   `ts > S_L` on a loaded key is therefore overwritten by the loaded value.
   Gate probe: load k at S_L = 10, Put k at ts 20, then `scan(7, 30)`
   returns `"loaded"`. Card 2.1 places a load's entries *at ts `S_L`*, so
   the newest version ≤ S must win. As written, the model agrees with a
   store that loses post-load updates. That is a masked failure.
4. **The (ii) completeness half has no test** (G2 is UNCAUGHT). Add a
   must-fail case: amcheck (ii) ran, a slot in `tainted_image_slots_ii` is
   not reported, and everything else passes.
5. **O-3 (c) fails open without a twin.** The false-positive rule is
   skipped when `twin` is `None` in an MP/MW round that has XX001. A
   missing twin is a harness defect. Make it fail the round, as the R
   guard does ("a harness defect must never pass").
6. **Smaller sim and oracle fixes.**
   - (a) `apply_crash` sets `cur = durable` without truncating to
     `durable_len`, so a synced shrink comes back after a crash (probe:
     length 4096, but the old bytes are readable at 4096). No current
     caller shrinks a file, but it violates 1.1.
   - (b) O-3 (c) maps a MISDIRECTED fault only to its source slot, while
     condition 1 counts the landing slot too. A detection caused by the
     stray bytes landing on a referenced slot is then called a false
     positive. Count the landing slot in `page_slots` as well.
   - (c) `apply_media_wal` faults only the lowest-id WAL file that has
     candidates, so in multi-segment seeds the active segment is never hit.
     Draw uniformly over all candidate durable WAL writes.
