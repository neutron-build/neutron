## REWORK items (new; both are in files frozen for X-5b)

X-5b's Touch rule 2 freezes `src/oracle.rs`, so a defect there would be
an ESCALATE. Rule 3 limits `src/sim/` to named additions. Both items must
therefore be fixed in this stage, each with a new pinned test.

A. **O-3 (c) leaves out the landing range of a WAL MISDIRECTED fault.**
   This is item 6b's defect on the WAL side. `FaultTargets::collect`
   (`src/oracle.rs:273`) pushes only `(inode, off, len)`. Gate probe: in
   MW, a MISDIRECTED fault moves `[0,512)` of file 3 to offset 8192. The
   twin's recovery read `[8192,8704)`, and the round has XX001 at Replay.
   The oracle returns `O-3(c): XX001 with every media fault on unread,
   unreferenced targets`, a false positive that fails the round. This
   fails closed, but in the 10k campaign every such seed is a spurious
   failure, which X5-R3 answers with a full re-run. Fix: also push
   `(inode, to_off, len)` for MISDIRECTED faults.
B. **The accept hook fails open when no single read covers the accepted
   range** (`src/sim/disk.rs:614`). Gate probe: two tainted reads,
   `[0,4096)` and `[4096,8192)`, then `accepted(f, 4000, 200)` gives
   `served = 0`. An accept with no read at all in the round also records
   nothing. The current draft's WAL reader reads from each record's own
   offset, so it does not hit this case today. But a record that is
   reassembled across batch reads, or an accept with no preceding read,
   would serve corruption without the hook seeing it. Fix: either judge
   each accepted byte against the most recent read that covers it, or
   treat "no covering read" as a served corruption or harness defect.
   Either way, it must fail closed.
