## Item B: fixed, fails closed; one pin missing

`SimDisk::accepted` (`src/sim/disk.rs:629`) walks this round's reads,
most recent first. It subtracts each read's coverage from the
not-yet-judged sub-ranges, so each accepted byte is judged once, by the
most recent read that covers it, at sub-range granularity. Anything left
uncovered goes into both `uncovered_accepts` and `served`, so O-3 (a)
fails the round whatever the harness does. `new_round` clears the new
list.

- **The gate's probe.** Two tainted reads `[0,4096)` and `[4096,8192)`,
  then `accepted(f, 4000, 200)`. This is now served; it is pinned by
  `accept_hook_judges_across_reassembly_reads`. Clean re-reads of the
  same range are not served again.
- **Fail closed.** An accept with no read in the round, and an accept
  that runs past the end of the read, are both served; pinned by
  `accept_hook_fails_closed_without_covering_read`. My probes also fail
  closed on a hole between two reads (`[0,100)` + `[200,300)`, accept
  `[0,300)`) and on a read of another file that covers the range.
  Zero-length accepts judge nothing.
- **The gap (B3, uncaught).** Mutant B3 judges taint only on the most
  recent overlapping read, while still computing coverage correctly. It
  passes all 53 tests. Both reads in the pinned reassembly test are
  tainted, so the test cannot tell "per byte" from "the newest
  overlapping read decides". My probe catches B3 and passes on HEAD: the
  older read `[0,4096)` is tainted, the newer `[4096,8192)` is clean,
  and `accepted(f, 4000, 200)` must be served. **The code is correct.**
  Only the pin is missing. This does not block: nothing today can
  regress `accepted` without a gate. But per-byte judging is the
  substance of item B, so the pin is a followup.
