# Defects (fix before merge)

1. **The pgvector arm measures the wrong thing.** `src/vector.rs::emit_pg_search_sql` orders by `v <=> q` — pgvector's **cosine** operator — while `workloads/vector-sift1m-pgvector/driver.sh` builds the HNSW index with `vector_l2_ops` (L2) and recall@10 is scored against the Euclidean SIFT1M ground truth (the Qdrant arm correctly uses Euclid). Three consequences: the L2 HNSW index cannot serve a cosine ORDER BY, so every query is a 1M-row seq scan (the card's "HNSW m=16, ef_construction=200" claim does not apply to what runs); `SET hnsw.ef_search` is a no-op (the ef sweep measures nothing); and cosine ranking against Euclidean truth yields a systematically wrong, unfairly low recall for pgvector. Nothing in the harness detects this — exactly the mismeasure-not-crash case. Fix: use `<->`. The row must then be (re)measured; the running chain's pgvector output must be discarded.
2. **Card Goal unmet: 3 of 7 E3 rows have no results at tip.** `vector-sift1m-qdrant`, `vector-sift1m-pgvector`, `embedded-sqlite-speedtest1` have workloads and two recorded init-digest expectations, but no results JSONs; a detached chain (`work/chain6.sh`, PPID 1) was mid-`embedded-sqlite-speedtest1` cold-0 during this gate. The worker never wrote a RESULT block (sessions died on bookkeeping). All seven rows plus a final acceptance run on the finished tree are required.
3. **The card's central invariant is untested.** Mutant M2 (invert the strict-digest comparison so a mismatch no longer voids/stops the run — §5.2 rule 4) passes all 68 tests. Extract the expectation-compare/void decision into a unit-testable seam and cover: first-run-record, match, mismatch-voids-and-stops, smoke-expectation isolation.
