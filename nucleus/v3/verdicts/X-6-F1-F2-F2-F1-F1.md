### R5 (blocking, rows, P): FG10 picks its commit at random and sometimes aborts the whole suite
FG10's setup, `test-enforcement.sh:3119`, runs `ls-tree -r --full-tree "$c" | wc -l`. The runner-ledger section defines a shell function `wc()` at `:2858` (from cb1a3c27, an earlier card), and it shadows `/usr/bin/wc`. That `wc` reads its own heredoc and prints nothing.

**Effect:**
- Every width is empty, so `sort -n | tail -n 1` picks the branch with the highest hash. That is a random choice among the 121 branches.
- When the pick is `scratch/prev3` (the pre-v3 root commit, made at `:464`, with no `nucleus/v3`), `fgstub` hits ENOENT. Then `git add` exits 128 and `set -e` kills the suite.
- Even in passing runs, FG10 never measures "the widest commit" it claims to.

**Shown:**
- Four instrumented runs printed an empty count for every branch, and four different picks.
- In my gate run, the pick was `prev3`.
- With `command wc -l`, FG10 picked the true widest commit (25 entries).

Merged as-is, this aborts roughly 1 in 121 runs of every later gate.

**Fix (P, FG10 is a non-forging row the card added):**
- use `command wc -l` at `:3119`;
- add a premise row: `$fgw`'s width is a number greater than 0, `$fgw:nucleus/v3/scripts` is a tree, and no branch is wider.

This edits only a row this card added, so no base row changes.

### R6 (blocking, rows, GLM forged-object): the lone-CR refusal is not pinned
My FG-LONE-CR-OK mutant changes the awk to `if ($i == "0a" && p != "0d") bad = 1` and drops the END clause. It passed all 681 rows. The check is load-bearing. Probed on 2.47.3 under `f.ps1 text eol=crlf` (the repository's own `.ps1` rule):
- The tree blob is `x=1\r\n`, committed raw. Its honest checkout is `x=1\r\n`, because a blob with no lone LF is not converted.
- The forged loose blob `x=1\r\r\n` checks out as `x=1\r\r\n`.
- `hash-object --path` of that file equals the tree id.

So the mutant would accept bytes the honest checkout never writes.

**Row FG11e** goes in the GLM block before its closing `no_state` row, in the FG11d pattern:
