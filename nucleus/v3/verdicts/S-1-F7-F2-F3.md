## R1: holds

The space is bounded by the trees ever created, and step 3 now says so.
- Every directory split is caused by an insert, inserts are one per tree ever created, and nothing frees a directory page: the last step does not pack, §10.4 does not visit the directory, and with no unlink a directory root never collapses. So pages are O(trees ever created).
- C-T6-rehost §6 confirms the id argument: one `next++` per counter behind a mutex, values may skip across a crash and never repeat. "At or near" the right edge correctly allows for a CreateTree that runs later than its id was allocated. The text does not claim that no leaf is ever refilled.
- I-SPACE is stated of a swept tree (§11), so an unswept directory breaks nothing.
- **T6's trigger is sensible and is not an owner promise.** It sits under a "Known cost" heading like T5, says "then a card defines", names no release and no owner, and T4's "owner decision" wording shows what a promise looks like here. The 1% is an implementer's round number: roughly 130,000 retired trees in a 1 GiB file. "Dominates open time" is unquantified. Unlike T1, T2 and T5, T6 names nobody who measures it, so it fires only on a report, as Q1 does. Acceptable for a cost this small (follow-up (d)).

## R2: holds

Every kind of page was checked against "a page that can be freed":
- Inner and leaf pages come through a latched parent or a re-descent; a pin taken in between names nothing without re-validating.
- A tree's root comes through the table.
- An overflow chain comes from its entry, under the leaf latch or a registered `S`. I-GC-READEQ keeps the version. A drop cannot pass a registered `S` that sees the tree (§6.6, C-T6 §7.5). Conversion moves a chain rather than freeing it. A tag-8 chain that is freed is one no other reader may read.
- `dir_root` and the other directory pages are never freed, so they are outside the claim, and only directory changers latch them. Map and FreeSet pages are physically addressed, not LPIDs.

Evictors and step 2 reach frames, not page names, and are not "readers".

## R3: holds

**A correct concurrent drop cannot reach XX001.** The last step removes the table entry before it frees the root, so a pin that sees the free has its re-read see the removal. CreateTree maps before it installs, so a thread that read the entry sees the mapping. The directory-change case (the last step, holding its directory leaf) can only meet this on corruption, since one walk runs per tree.

**A retry cannot reach it either, and the retry is bounded.** An entry only goes `live` -> `dropping` -> absent and ids are never reused, so at most two changes occur, and absent stops at (1).

**The check is race-free.** The same monotonic triple is compared as at (3), so there is no ABA. It needs the table read and the pin to synchronise with the map change, the same dependency as (3), which A-7b's mechanism must meet.

**Healthy data.** No image holds an entry with an unmapped root (§6.8), and replay frees nothing, so recovery and read-only open are safe. One precision is missing. The rule says "finds the LPID unmapped", but §4.1 defines unmapped as `slot = 0`, and the spec does not say what a resident, never-written page's entry holds or that a pin looks at the page table first. The spike does look there first (`fetch_page`, frames before `map.cur`), and with that order an eviction sets the slot before the frame goes, so no false unmapped exists. A map-first pin could raise XX001 on a healthy never-written root, which under the old retry rule was harmless. No correct reading of today's text requires that order, so this is not blocking, but it should be closed before A-3 cuts the pin (follow-up (a)).

**The R3 contradiction is resolved.** §6.8's open sentence, §14 step 6, §9.2's drop-walk bullet and the new rule now agree: a boot walk on a corrupt image raises XX001 and poisons.

**Case E and ROOT-PIN-UNMAPPED-SPIN are legitimate.** A rule change with no test would be unpinned, SPIN is exactly R3's bug, the step budget catches it, and FATAL still fails case C. Two precisions go to the follow-up. A pin that hits a resident frame never sees the map, so the fixture must evict `r` as well, and a fixture that does not fails loudly on correct code. "No case poisons the store" holds only if A is a client read or a stand-in, so a gated A would contradict §9.2. The poison arm itself, a real walk raising XX001 and poisoning, has no test; `t_gated_xx001_poisons` uses a damaged leaf.
