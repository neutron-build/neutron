## Findings

1. **ESCALATE 1 is a real defect and it blocks the merge.** It is worse than the worker and the pre-gate say. (a) The wrong answer does not just come early. With one clean frame and the rest pinned, the correct outcome is to wait for the latch holder and then for an unpin (§5.4: "A thread that cannot pin a frame because every frame is pinned waits for an unpin"). `PoolStarved` is never right there: no frame is dirty, so even OP-4's interim licence ("every unpinned frame is dirty") does not hold. The pre-gate's "the answer equals the honest one a retry later" is false for this layout, which its own model counts (row "F=2: C P", 418 interleavings). (b) It breaks R-1-memory §4.4 ("a thread that may still pin always finds a (U) frame, and waits at most for its brief latch holder (S-STORE §5.3)") and §5.3's fairness bound ("so the operation waits only for such a frame's brief latch holder"). Both sentences are unchanged at the scaffold. (c) The consequence is serious. S-STORE §9.2 says 53200 "poisons the store when it is raised inside … a gated operation … whether or not the operation has mutated a page yet". A gated operation past its first mutation must use the waiting `reserve()` and `pin` (§5.3). So once A-3c maps the error and A-4a gives the pool engine callers, two racing acquirers can poison a healthy store. A-3c's Work 8.3 keeps "A-3b's rule", so the defect would be inherited. **Where it lies:** in Work 5's steps and their third bullet. They are not in the code's reading of the card, nor in the spec.
2. **ESCALATE 2: the no-hang rule fails for card rows 11, 15 and 17.** This is confirmed above. The worker reported only 15.
3. **Three sites no test judges** (all confirmed as survivors): `notify_one` with two waiters; `Kept` not setting `busy`; `VictimGuard::pin_frame` setting the bit.
4. **The worker's RESULT is incomplete.** It has no Work 0 record and no test names (counts only), and it under-reports the hangs. It also does not report three deviations from the card's text: `transition_table`'s dirty row expects the bit cleared (correct by A2's own order), `poisoned_table` became `pub(crate)` with `Table::reserve_free`/`Pool::build` factored out, and `hash_placement`'s 64- and 1000-frame pools moved to the test-only constructor. All three are harmless.
5. **Nit:** `store.rs`'s `PoolStarved` doc ("Every frame stayed pinned across two full clock sweeps") and its `#[error]` text are false on this card's path. Limit 2 forbids the change here (A-3b-0-F3).

- Replace A6 with:
  > - **A6.** If some frame is Resident with count 0 (a scan of `meta`): unlock; if `busy`, call `buf::sync::yield_now()` and go to A1; otherwise go to A6′. (gate ruling A-3b-0 R1)
  > - **A6′. The own pass.** Visit every frame `f` in frame order, `0` to `F − 1`, without moving the hand and without reading or changing a reference bit: lock; read `meta[f]`; unlock; if it is Resident with count 0, call `try_victim(f)` and treat the answer exactly as A2 does (`None`: `busy = true`; dirty: drop the guard; clean: `remove_from_table`, where `Removed(res)` means lock, `evictions += 1`, unlock, fire `Evicted(k, f)`, return `res`, and `Kept` means `busy = true`). The pass fires no `SweepEnded`. After the last frame: if `busy`, call `buf::sync::yield_now()` and go to A1. Otherwise lock; if the free list is not empty, or `unheld_events ≠ g0`, or no frame is Resident with count 0, unlock and go to A1; otherwise unlock and return `Err(StoreError::PoolStarved)`. (gate ruling A-3b-0 R1)
- In "Why the decision is exact at this card", replace the third bullet ("Hence, at A6 with `busy` false, …") with:

A frame that is unheld at that hold has been unheld and Resident, with the same key, since A1, because every way back to unheld passes through U1–U4. The pass latched it and found it dirty. Only a holder of its exclusive latch can clean it: a pin holder, whose unpin would have moved the generation, or a victim's holder. At this card no store path cleans a victim and leaves it in the table (only tests call `VictimGuard::mark_written`). So every unpinned frame is dirty. Dirty frames leave the page table only by A-3c's dirty eviction, so `PoolStarved` is the right answer here, and A-3c replaces it.
