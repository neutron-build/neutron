# Findings

1. **STILL-ACTIVE-SILENT uncaught (minor, non-blocking).** Deleting the `unit still active after waiting 60s` `eprintln!` leaves the full suite green: no test covers the poll-expiry report. The card prescribes the behaviour (Work 2) but deliberately names no test for it — covering it deterministically would hold a unit active for the full 60 s per test run. The code path is three lines and straight-line; not worth a follow-up card on its own. If a future card touches `unit_stop` again, a child-re-exec test with a shortened (parameterised) wait would close it cheaply.
2. **Cosmetic: the `is-active` poll inherits stdio.** The 200 ms poll runs `systemctl --user is-active --quiet` with inherited stdio; for an *invalid* unit name systemctl prints `Failed to retrieve unit state: …` straight to the harness console (observed during mutant 1, where the report line was suppressed and the leak became the only output). Real `nbench-*` unit names never hit this, `--quiet` keeps valid names silent, and the report test's assertions are unaffected. Capturing the poll like the stop call would make it fully silent; cosmetic only.
