## SIGPIPE ruling
In both `rv11_fp` and `rv11_full`, `git rev-list` is piped into `grep -q` under pipefail. When grep matches, it exits, and git can then die of SIGPIPE, so the pipeline exits 141. Probe: `set -o pipefail; {echo a; echo b; sleep .2; echo c;} | grep -qxF b` exits 141.

- **`rv11_fp` (negated) is safe.** The SIGPIPE case can only happen when grep matched, meaning B is on the first-parent list. In that case the premise really is false, so it reports correctly either way. A no-match never triggers SIGPIPE.
- **`rv11_full` (positive) is the side that can flake.** A true premise can read as false. The failure is fail-closed (never a false pass), and the risk is small: the listing is a handful of commits. However, I saw the identical shape fail once: `premise: RV8 rev-list O -- lists F` (`rv8_oldlist`) FAILed, with no output, on my unmutated baseline copy while five suites ran in parallel. It passed in every other run. That is not blocking for this card (Follow-up F1).
