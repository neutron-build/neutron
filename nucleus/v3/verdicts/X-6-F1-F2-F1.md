  rows use GIT_CONFIG_PARAMETERS per command. Nothing in this card blocks it.
- **Helper interface for X-6-F1-F2-F3 (the commit-graph gap).** `gshim verify`
  works for CG-VERIFY-FAIL-OPEN. The exit is fixed at 128, git's real fatal
  code, distinct from the exit 1 that `commit-graph verify` gives on a bad
  graph, so an implementation can tell "cannot run" from "fails verification".
  Calls are prefix-scoped, so gs, out_has and audit-merges can be wrapped.
  **Gap:** the shim's exact matching is implemented but not pinned
  (GSHIM-SUBSTR UNCAUGHT). Premise 1 uses `no-such-word`, which a substring
  shim also passes through. F3's word is `verify`. merge-card.sh,
  promote-pass.sh and enforce-lib.sh all call `rev-parse -q --verify`, and
  enforce-lib backs audit-merges. A future edit to substring matching would
  fail those calls too, and an F3 caller row could then pass for the wrong
  reason. Filed as X-6-F1-F2-F1-F1.
