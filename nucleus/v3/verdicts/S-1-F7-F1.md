## R1: fixed

- **(a) Identity.** §10.4 "Chains first" now makes each separate delete conditional on identity (C-T0 v8 §2.4 (c)), checked under the leaf's exclusive latch: an older version by `k@ts`, a tag-8 entry only while its bytes still show it dead. A current-boot entry at the key is left alone, with its chain. §10.2's chain sentence says the same ("only while it is still the same entry").
- **The premise, tested against the spec.** "No entry becomes dead within a boot" holds. C-T0 v8 §2.4 defines dead as `txn.boot` ≠ the current boot id. §2.5 and S-STORE §14 step 8 fix the boot id once per read-write open, at the boot checkpoint, before any txn starts, and nothing changes it until the next open. So an entry's deadness is fixed for the whole boot. Every provisional entry written while a sweep runs carries the current boot id, so it is never dead. A read-only open, where every entry is dead, writes nothing and runs no GC. Recovery writes no provisional entry (§2.4: committed data comes only from the WAL). Every other path that touches tag-8 entries (owner rewrite, conversion, settlers (a)–(c), the prune) only replaces or deletes them. So a dead entry found at `entry_key(k, u64::MAX)` after the gap is the one the step marked: one entry per key, and no new dead entry can appear there. For older versions, §10.1 condition 2 forbids any insert at `ts ≤ w`, so `k@ts` is never re-created, and ordinary versions are never rewritten in place.
- **(b) Termination.** The new argument holds and is better than the prior verdict's window-prefix one: it does not depend on how splits move the window. The markable chain-bearing entries past the position depend only on the entries `≤ w` (which change only through GC, §10.1), on deadness (fixed per boot, above) and on the carried state (unchanged by these deletes). No insert adds to that set, the prune and settlers only remove from it, and each round removes every entry it marked (deleted, gone or replaced). The set is finite, so the re-runs end, and writers cannot livelock the step.
- **(c) Fixtures.** `t_sweep_step_shape` now runs at height ≥ 2 (so `P` exists) and holds both races. (a): an elided-tombstone group ending in `L`/`R` with chain-bearing older versions and no version above `w`, read between every two of its deletes. STEP-MUTATE-BEFORE-CHAINS deletes the tombstone first, and the next read finds an older version, against the row's "finds no version". (b): a hook-driven writer settles the dead tag-8 entry and writes its own, then stays `Open`. CHAIN-DELETE-BY-KEY deletes it, which the owner's read and amcheck's chain check catch. Both mutants are named in rows inside Limit 2 (I-GC-READEQ, I-GC-ORDER).

The card picks one and argues liveness.
