**Non-blocking findings.**
1. **GC tombstone elision is narrower than the card's text.** The code
   elides the kept ≤ W tombstone only when no version above W exists
   (`above_w == 0`). The card says "nothing older remains", which always
   holds after the deletes. Keeping the tombstone is safe but leaves extra
   tombstones, which inflates arm (b)'s space amplification. The doc
   rationale ("nothing above the watermark left to separate readers from")
   is also wrong: deleting it would be equally invisible. → X-2-F1.
2. **S13 never runs under eviction.** The card's "pool = 64 frames so that
   eviction is exercised" is unmet by construction. Each schedule fits one
   8 KiB leaf, so the seeded differential never meets a page miss, and s14
   covers eviction only for one bulk txn. → X-2-F2.
3. Notes only, no card:
   - `gc()` ignores the poison flag (it uses `self.store`, not `usable()`).
     It only deletes ≤ W versions, so it is harmless.
   - `gc()` pass 1 holds a whole-tree range cursor, so writers on the
     latched path stall for the duration of the pass.
   - `scan` materialises the whole `[lo, hi)` regardless of `limit`. This
     is the shared W-MERGE pattern (RefEngine does the same).

   X-4 should read GC and scan cost with the last two in mind.
