# Rulings on the card writer's P decisions

**J3: CONFIRMED.** A PATCH of `indexing_threshold = 1` KB after upload is a fair, like-for-like configuration:
- the row's protocol is "HNSW m=16, ef_construction=200", and the pgvector arm's `CREATE INDEX … USING hnsw` covers every row;
- under the default 10000 KB, whether the ~16k-vector tail is a graph or an exact scan depended on segment layout. That is a property of the run, not of Qdrant.
- The knob is build-time only. It changes no search parameter, no HNSW parameter and no segment count, and it is vendor-documented. Qdrant's own bulk-load guidance toggles this same setting.
- The rule is unconditional and recorded in `collection-info.json`.
- It is consistent with B-0's treatment of pgvector, whose driver sets `maintenance_work_mem = '2GB'`: a vendor-documented build setting, published in the driver.
- It removes a cost that hurt Qdrant (server p50 1.8 vs 0.21 ms), so it is not tuning against the competitor.
- "Anything else is ESCALATE" is right.

Caveats, binding:
- J3 is scoped to static-load rows. A churn or ingest row (E8) must not inherit threshold 1 without its own P ruling, because it forces HNSW builds on tiny segments during ingest.
- J3 must appear in the §5.2 rule 2 vendor-review config.
- `rows.rs`'s comment "Defaults are Qdrant's documented production defaults" is now false (B-0-F7-F1-F1).

**J6: CONFIRMED.**
- It is pre-registered correctly. It is fixed in a P card before any data exists, the code applies it verbatim, and the five mutants on it are caught.
- Extending it from ef16 to every ef point is a legitimate tightening made before the data. E3 uses the whole recall/QPS curve: the §5.3 vector target, recall ≥ 0.95, lives at ef ≥ 32. An ef16-only rule would certify a row whose other points do not reproduce.
- It is not so strict that honest runs fail:
  - Each cell is a warm median of 5 passes × 10k queries, and with an identical index state run noise is a few percent, well inside 15%.
  - The real variance is build-to-build HNSW randomness. That is exactly what a baseline must survive.
  - Two fully indexed builds differ at ef16 recall by 0.0013 (0.9410 committed row vs 0.9397 smoke; an order of magnitude only, not a measurement), inside 0.002. At ef ≥ 64 the recall differences are smaller still.
  - The tightest cell is ef16 p50 (~0.3 ms, so ±0.05 ms).
  - 15 comparisons raise the family-wise false-failure rate somewhat. That is acceptable because NOT-REPRODUCED escalates to P rather than losing the card, and C1 cannot rest on a row that fails J6.

**J2 vs the parent's non-reproduction: CONFIRMED.**
- The predicate requires `indexed == points` on every poll of the window. The gate's 984,064/1,000,000 state held for 60 s stays Waiting; this is tested, and the SETTLE-PARTIAL-INDEX mutant is caught.
- That state can therefore never be measured. It now ends in the 3600 s / 300 s timeout, which is a refusal.
- Qdrant documents `indexed_vectors_count` as approximate. Strict equality held in 3/3 builds. If it ever does not, that is a J3 ESCALATE, which is fail-closed and the right direction.

# Findings (REWORK; all in Touch-only files)

1. **R1 (blocks F1b): `reproduce.sh` never finds a successful run A.**
   - `dir_of_run_a` (line 91) tests `$d/run-a.json`, but `run_one` writes `$d/vector-sift1m-qdrant.run-a.json` (line 111). `do_verdict` and `do_check` also locate the dir through `dir_of_run_a`.
   - Reproduced with a stub `NB_BIN` (quiet wait bypassed, `/tmp` root): `a` exits 0; `b` then refuses with exit 4, "run A has not finished"; `verdict` also exits 4.
   - On real hardware, F1b would burn run A's quiet window and then have to ESCALATE.
   - No test or Acceptance line exercises `b`, `verdict` or `check`.
2. **R2 (breaks F1b's no-rerun rule): a voided run is re-runnable.**
   - On a digest mismatch, `nbench run` writes the results JSON and prints `results:`, then exits 1 with "VOID (digest mismatch)". The log contains no `FAILED`.
   - `set -e`/`pipefail` aborts `run_one` straight after the `tee`, so the voided JSON stays as `results/<date>/vector-sift1m-qdrant.json`.
   - The next `reproduce.sh a` classes the log as a killed attempt, renames it and runs again. Reproduced with a stub.
   - F1b says "a run that wrote a results JSON … is final". J6's `digest.voided` → INVALID arm can never fire, because a voided JSON never reaches `repro/`.
3. **R3 (loses the evidence F1b's escalation needs): a refused run's index-state evidence is not preserved.**
   - On a FAILED run the script aborts before copying `work/<date>/<row>/` into `repro/run-x/`. Run B, on the same UTC date, then overwrites that same work dir. Reproduced with a stub: only run B's state files survive.
   - For a J4 refusal, the both-states diff is printed only to the gitignored `<pass>.settle.log`. `settle_pass` sends it to stdout through `2>&1 | tee`, and the search's `NB_LOG` is never written.
   - So by `failure_message_tail` the FAILED line will carry "no stderr; log … unreadable", not the diff. That last point is inferred from the code, not reproduced live.
   - Fix: on any run outcome, copy the evidence, including `*.settle.log`, before exiting non-zero. Also make the settle's mismatch reach the FAILED line, for example by teeing it to stderr.
4. **R4 (test gap): G6 is uncaught.** Dropping the "warm aggregate lacks index_segments" INVALID arm passes 130/130. Add a case to `repro_verdict_applies_the_preregistered_rule_verbatim`.
5. **R5 (minor, fix in the same rework):**
   - `run_one` runs `mkdir -p "$REPRO"` before `quiet_wait`. An exit-3 on day D leaves an empty `results/D/repro`, and a run on D+1 then fails `check` and F1b Acceptance #1 (two repro dirs). Create the dir after the wait.
   - `live_nbench_units` uses the default `list-units`, which also lists failed units. A stale failed `nbench-*` unit makes the host never quiet. This is safe (exit 3) but blocks F1b. Restrict it to active and activating units.
   - A debug `NB_BIN` makes `run` exit with no `FAILED`, which silently consumes the one killed-attempt retry. Check the profile, or the refusal text, before starting.

**Acceptance for the rework:** a stub-driven test of `reproduce.sh` (fake `NB_BIN`, quiet wait injectable) covering success a → b → verdict → check, a FAILED run A, and a VOID run A. It must be committed as an outcome-neutral script and listed in Acceptance.
