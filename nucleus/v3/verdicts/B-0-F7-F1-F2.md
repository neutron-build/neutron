# Findings

1. **(verified, fixed) run-b/ inheriting run A's leftovers** — the
   parent verdict's finding 1 is closed by the `-nt` filter; J6 is
   untouched (`derive_verdict_output` reads only run JSONs/logs, and is
   unchanged).
2. **(minor) S5 cannot catch a marker that is not refreshed per run.**
   Own mutant EV-SHARED-STALE-MARKER (one shared marker name, touch only
   if missing) passes the whole selftest: the card-mandated −1 h backdate
   puts run A's leftovers before run A's *own* marker too, so a stale
   marker still excludes them. If B-0-F7-F1b-F2 (which edits this same
   `run_one`/`selftest`) reverts to touch-if-missing, run-b/ silently
   starts receiving run A's files again and no test fails. The shipped
   `touch "$marker"` is unconditional and per-run — correct today.
3. **(minor) mtime semantics unpinned.** A full-granularity ctime filter
   (the `-cnewer` analogue) passes the selftest: `touch -d '-1 hour'`
   cannot backdate ctime, but S5's touch runs before marker-b, so stale
   files' ctime also precedes the marker. A seconds-granularity ctime
   filter "fails" only by quantization luck (FAIL-set varies per run).
   Only exotic metadata ops on leftovers (rename/chmod) would make a
   ctime filter actually wrong.
4. **(note) the tracked-path rule is review-only.** Marker under
   `results/` passes the selftest (scratch roots are not repos). The
   shipped marker lives under `bench/nbench/work/`, which `.gitignore`
   ignores — verified.
