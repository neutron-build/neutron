## Findings

**Gate run.** The first run printed `STEP test EXIT=127` because the gate
shell's PATH did not include `~/.cargo/bin`, so `cargo` was not found. This
was an environment problem, not a defect in the card. After adding
`~/.cargo/bin` to PATH, every STEP on the clean tip f5ced0b3 printed EXIT=0
and the run ended `GATE EXIT=0`.

**Scope.** All 16 changed files are under `nucleus/v3/spikes/e0-btree/`, and
no protected path is touched. The workspace's `spikes/*` glob picks up the
crate, so `Cargo.toml` did not need an edit. `rusqlite` (bundled) is optional
and is enabled only by the `sqlite` feature. It is used only in
`src/bin/e0-bench.rs`, under `#[cfg(feature = "sqlite")]`, and the README has
the required justification. There is no `unsafe`, no `mmap` and no
concurrency crate. There is no non-test `unwrap`, `expect` or `panic`.
`indexing_slicing` is denied in `page.rs` and `tree.rs`, and every pub item
is documented.

**Correctness.** I re-derived the following and found them sound:
- The page layout and its bounds checks.
- The split arithmetic. With 8 KiB pages and `MAX_KEY` set to 2000, both
  halves always fit.
- The separator semantics. A cell `(child, s)` covers `[prev, s)`. On a split
  of a middle child, the left child's bound is lowered and `(right, old
  bound)` is inserted.
- The budget for the two parent edits against `is_safe`. The net growth is at
  most `MAX_INNER_COST`, so a safe parent never overflows.
- Root-split handling under `RwLock<PageId>`, including the re-check after
  latching the root.
- The cursor-stack range scan, which uses no sibling links.
- The pool's pin discipline. Pins are raised under the table mutex, and only
  frames with zero pins can be victims.

Writers always take the root latch exclusive, and every open `RangeIter`
holds a shared latch on the root. This is how classic crabbing works and the
README documents it. It is the reason the readers in `concurrent.rs` sleep
between scans.

The worker quoted the decision rule verbatim (ours ≥ 0.8× SQLite on W-point

root latch.

**Findings (none blocking):**
1. The `propagate_split` → `find_parent` fallback (`src/tree.rs:555`,
   `:653`) is dead in correct code. With it replaced by an error, the full
   suite plus 5 runs of `concurrent.rs` stayed green. It also masks
   latch-coupling bugs. G-SAFE-LAX40, an `is_safe` that is too lax, passes
   every test. If the fallback returns `Corrupt` instead, `model.rs` catches
   that mutant deterministically, with 1019 hits. This also conflicts with
   the §6.1 rule against dead code. → X-0-F1.
2. Error paths are not atomic. If `new_page()` fails with `PoolStarved` or
   an I/O error partway through an insert, the tree is left damaged:
   - an upsert has already removed the old cell (`tree.rs:480` → `:514`);
   - a parent has already had its bound lowered with no right sibling
     installed (`:612` → `:636`).

   Pages are also modified without `mark_dirty` before the error returns. In
   `pool.rs:247`, a failed `store.read` leaves the frame with its old id and
   a possibly stale dirty bit, while the table entry is already removed. A
   later eviction can then remove another frame's mapping for the same page
   or overwrite it. → X-0-F2.
3. `check()` is weaker than its doc says (`tree.rs:425`). Child 0 of an
   inner page gets the lower bound `None` instead of the parent's `lo`, and
   separators are never checked against the bounds inherited from above.
   The op-by-op model comparison covers this today, but X-1a…X-5 will lean
   on `check()` alone. → X-0-F3.
4. Minor issues:
   - The W-mt "ratio" printed by e0-bench is SQLite ops/s ÷ ours, which reads
     inverted under the ">1 = we are faster" legend (`e0-bench.rs:582`,
     `:637`). The README table states it correctly by hand.
   - All 4 reader threads in `concurrent.rs` use the same seed (`:145`), so
     they scan identical ranges.
   - `compact`'s `cur -= len` and `hole_bytes` can underflow on corrupt
     overlapping slots and panic in debug builds instead of returning
     `Corrupt`.
   - `examples/dbg.rs` is an empty scratch file.
   - G-EVICT-PINNED is caught only as a hang.

   → X-0-F4.

## Follow-ups

**X-0-F1 (S, before X-1a/X-5 build on the tree):** Replace the
`find_parent` re-derivation in `propagate_split` with
`Err(StoreError::Corrupt("descent path desync"))` and delete `find_parent`.
Then show that G-SAFE-LAX40 (`is_safe` with `need / 40`) is caught by
`model.rs`, and that COUPLING-EARLY-RELEASE is still caught by both
`model.rs` and `concurrent.rs`.

**X-0-F2 (S):** Make insert and split atomic under errors:
- pre-allocate every page a split cascade could need (one for the leaf, plus
  one per retained ancestor, plus one for a new root) before mutating
  anything;
- or work on copies and publish them only on success.

Mark a page dirty before its first mutation. In `BufferPool::locate`, on a
read failure, reset the frame (`id = None`, `dirty = false`) after the old
page has been written back. Add a test with a fault-injecting `PageStore`
that fails `allocate`, `read` or `write` at the Nth call, and then asserts
that `check()` is clean and the model matches.

**X-0-F3 (S):** In `check()`, pass the parent's `lo` to child 0. Assert that
every separator s of an inner page satisfies `lo <= s < hi`. Add a unit test
that hand-builds a 3-level tree with a misplaced separator and a misplaced
key in a leftmost subtree, and expects `check()` to fail on both.

**X-0-F4 (S, mechanical):** Fix the remaining minor issues:
- print the W-mt ratio as ours ÷ SQLite, or label it as throughput;
- seed each `concurrent.rs` reader distinctly;
- use checked subtraction in `compact` and `hole_bytes` and return `Corrupt`
  instead of panicking;
- remove `examples/dbg.rs`;
- add a debug-assert in `victim` that the chosen frame is unpinned, so a
  pinned-frame eviction fails fast instead of hanging.
