## Round-1 findings

R1 fixed and real. `pidsForProfile()` scans `/proc/*/cmdline` for the
run's unique profile directory, `sigkillBrowser()` SIGKILLs the matches,
waits for them to leave `/proc`, and records
`{pids, signaled, remaining, killed}`. With `killed=false`, `method_error`
turns the scenario into `error`. The same sweep backs the timeout path,
`closeBrowser()`, and the exit/SIGINT handlers. Evidence from scratch:
- An instrumented copy logged the hit processes (Chromium
  `chrome-headless`, Firefox `firefox`, WebKit `pw_run.sh` bash plus
  `MiniBrowser`).
- Freeze test: the browser was SIGSTOPped inside T1 with
  `--step-timeout-ms=10000`. In all 3 engines T1 went to `timeout` with a
  kill record `killed:true`, the stopped pid (state T) was gone, and no
  browser process was left afterwards.
- Mutant G1 (the kill claims success but sends no signal) gave T2/T3
  `error` with "pids [...] survived SIGKILL" and DECISION FAIL.

R2 fixed and real. The README's full-run table (real-PID kills, 300/300,
flush p50/p99 0.3/1.1 ms Chromium, etc.) matches the worker's full-run
summary lines in `logs/X-6.attempt1.jsonl`, pids included. The gate
re-ran the full datasets on an unmodified scratch copy, and the result
was the same in all 3 engines: T1 pass, T2 tab and browser kill ok
(killed=true; 1, 1 and 2 pids), T3 300/300 with the WAL content exact, T4
pass, WAL exact, DECISION PASS. Only the p99 differs (Chromium flush p99
7.7 ms), and the README documents that p99 as jitter-prone. No raw JSON
of the full run is committed, though: `results.json` is gitignored and
overwritten (X-6-F2).

R3 fixed and real. `read_wal()` reads the file through the sync handle
from byte 0 to the frontier, which is seeded from `getSize()` at open.
`walCheck` compares byte for byte, and length too. Re-applying M1 (zeros
of the right length) failed T1, T2 tab, T2 browser and T4 in Chromium,
Firefox and WebKit (`first_bad: 0`, len 525/21), with DECISION FAIL.

R4 fixed. The `lib.rs` flush-boundary doc now reads "Only data written
before a successful flush is guaranteed…". The README has a "What PASS
does and does not show" paragraph: process death, not flush efficacy,
and the no-op-flush mutant is listed as inherently UNCAUGHT.
