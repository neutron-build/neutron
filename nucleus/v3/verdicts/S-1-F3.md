## R1: closed

**What the text says now.**

- **§14 step 8** gives a boot's id as the newest, in serial-number order, of three values:
  - `low32(ckpt_id)`;
  - the opened meta's `boot_id` + 1;
  - the newest accepted record's id + 1.

  This is the required sentence, verbatim.
- **§12.5's premise** now states the property the stop relies on: each boot's id is newer than the opened meta's `boot_id` and than every record its recovery accepted.
- **The new variant** of `t_boot_id_after_rollback` is round 1's trace step for step, and it carries `t_meta_rollback_crosses_boot`'s fixture constraints.

**Round 1's trace.** Boot `b+3` now gets max(k+2, k+4, —) = **k+4**, which is newer than meta k+1's `boot_id` (k+3). So the next open walks from `p`, accepts `b+3`'s records and replays its acked commits. BOOT-ID-NO-META-FLOOR reproduces the loss, and the variant catches it.

**Breaking it once more (pure MP: LOST meta writes plus ordinary crashes).**

1. **The newest visible meta never goes backwards.** Each slot only ever changes to a meta with a higher `ckpt_id`, and a LOST write leaves the slot's old content. So a boot X that opens meta M sees no meta newer than M. Every boot that opened anything between M's write and X's open also opened M. All of them truncated at a position ≥ `M.wal_start_lsn`.
2. **Bytes below `M.wal_start_lsn` are as they were when M was written.** Their ids are therefore ≤ the id of M's writer, which is `M.boot_id`. A boot checkpoint's `wal_start_lsn` is the append position. A later checkpoint's start belongs to its own boot.
3. **Each boot's id is strictly above the record just before its own records.** If X's recovery accepted something, the accepted-record floor gives this. If it accepted nothing, the meta floor gives it, by point 2.
4. **So the stream's ids never decrease, and they strictly increase at each boot boundary.** This gives what the ordered stop needs. It also makes `TxnId`s distinct across every boot that one walk crosses, so G1 (i) stays closed.
5. **Bonus.** Provisional entries in M's image carry ids ≤ `M.boot_id`, which is below X's id. So C-T0 §2.4's "not the new boot id" now holds by construction.

**The remaining shape.** A sibling boot W also opens M, and its first record is torn. W's id can then equal X's. W's later records are stale only after X's truncation is reverted. That needs MW and MP in one history, which is the §12.5 Residual exactly as stated. R1 does not widen it.

**Wrap-around.** Three-way "newest" is well defined under the existing 2^31 bound.
