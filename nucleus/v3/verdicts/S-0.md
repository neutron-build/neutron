### Defects (REWORK)

1. **Cwd-relative pathspec makes the CORE, docs and audit checks dead.**
   check-core-paths.sh:47 (`git diff ... -- "$v3"`) and audit-merges.sh:27
   (`-- nucleus/v3`) run from `nucleus/v3/`, so the pathspec resolves to
   `nucleus/v3/nucleus/v3`. The result: `check-core-paths.sh nucleus/v3-scaffold HEAD`
   on this card prints nothing, and `audit-merges.sh` examines zero merges
   (on v2-scaffold the same form finds 0 merges, against 90 with `:/nucleus/v2`).
   Evidence: an S verdict on a card editing `scripts/gate.sh` merged, and a
   Class: standard card with an S verdict adding `docs/X.md` merged. The audit
   then printed `ok`. Fix: use `":/$v3"` or `cd` to the repository root.
2. **`verdicts/` is in CORE_PATHS.** Once 1 is fixed, every card's own
   `verdicts/<ID>.md` counts as a CORE change, so no S-tier card can ever merge.
   With the pathspec patched, the audit flagged a spikes-only S card. Exempt the
   card's own verdict file.
3. **The verdict is not bound to the tip.** `Commit:` and `Card:` are never
   checked. Commits made after the verdict still merge: a commit that edited
   `scripts/promote-pass.sh` after an S verdict merged. Require that `Commit` is
   `tip^`, that the tip commit adds only `verdicts/<ID>.md`, and that `Card` is the ID.
4. **The audit only sees merges with merge-card's subject.** A plain
   `git merge --no-ff --no-edit card/v3-X`, plus a direct commit to `tools/`,
   passed the audit even with the pathspec patched. Audit every first-parent
   commit since the v3 root.
5. **promote-pass matches `GATE EXIT=0` anywhere.** A failing test that prints
   that line produced `STEP test EXIT=101` and `GATE EXIT=1`, and the pass was
   still pushed to the fake scaffold. Check the last line, or `PIPESTATUS`.
   Also require a clean worktree, and run queue-check (§7.6.5 says it runs at
   every merge pass).
6. **The runner's gate-last rule is a substring check.**
   `echo GATE EXIT=0 # scripts/gate.sh` is accepted and would pass. Require the
   exact gate command.
7. **Follow-up check by substring.** `T-1-F1` is satisfied by `T-1-F10`, and an
   empty Followups list or `none` with MERGE-WITH-FOLLOWUPS is not rejected. Use
   queue-check's ID-boundary and state regex.
8. **The CI workflow sits outside the tier check.** Changes are only examined
   under `nucleus/v3`, so an S card can edit `.forgejo/workflows/nucleus-v3.yml`.
   The CI docs step only warns, where §7.6.2 says CI fails. The audit's docs rule
   does not require `Class: spec`, although the verdict carries that field.
9. **No tests for the enforcement.** Only the matcher self-test exists, and none
   of the named mutants is caught by any test. Add a throwaway-repo enforcement
   test that runs the scenarios above, and call it from gate.sh. That test would
   have caught defect 1.
