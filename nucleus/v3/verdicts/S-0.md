### Defects (REWORK)

1. **S-0 cannot be merged by its own rules.** In the clone, with a MERGE
   verdict committed at the tip (Commit = 54120384), `merge-card.sh S-0` was run
   onto a scratch branch from 655197cb, using the real card file. It refused:
   `nucleus/v3/docs/README.md: docs/ changes need Class: spec and a P verdict`
   and `nucleus/v3/verdicts/README.md: a card may change only its own verdict
   file`. A hand-made merge would fail `audit-merges.sh` on the scaffold for the
   same reasons, permanently, because there is no escape hatch. Choose a rule
   that S-0 and later cards can satisfy, for example: exempt `verdicts/README.md`
   as a P-tier CORE file, and exempt `docs/README.md` as a P-tier index, or move
   it. Then add the bootstrap case (adding these READMEs) to test-enforcement.sh.
   Its BOOT setup creates `docs/` and `verdicts/` empty, which is why the tests
   missed this.
2. **Renames hide the source path.** `changed()` in enforce-lib.sh (`git diff
   --name-only`, renames on by default) lists only the destination path. An S
   card doing `git mv scripts/promote-pass.sh spikes/p.sh` was ACCEPTED by
   merge-card, and the audit then said ok. The runner's `changed_files` has the
   same blind spot: a rename from `docs/S-STORE.md` to `spikes/` gave no scope
   violation. Use `--no-renames` in enforce-lib.sh, in check-core-paths.sh, and
   in run_card.py's `git diff`. Use `git status --porcelain --no-renames`, or
   keep both sides of a rename. Add a test for each.
3. **The audit ignores evil merges.** The scenario: `git merge --no-ff
   --no-commit card/v3-A`, plus an extra edit to `scripts/gate.sh`, committed
   with merge-card's exact title. The audit said `ok (2 commits)`, because it
   checks `sha^1...sha^2` but never the merge commit's own tree. Require that the
   merge tree equals the clean merge result, e.g. `git merge-tree --write-tree
   sha^1 sha^2` compared with `sha^{tree}`, and add a test.
4. **The audit's path filter skips the CI workflow.** A direct commit on the
   pass that rewrote `.forgejo/workflows/nucleus-v3.yml` gave audit `ok`. The
   `rev-list` pathspec is only `:/nucleus/v3`. Add the workflow path, or audit
   every first-parent commit since the v3 root that touches any path
   merge-card treats as P.
5. **TIP-UNBOUND is not caught by any test.** Removing both tip checks (enforce-lib
   lines 42 and 44) still passes the whole suite. Test G's late commit edits
   `scripts/promote-pass.sh`, so the CORE rule refuses it before the tip checks
