## Follow-ups (non-blocking)

- **S-0-F1: no test for the Commit binding.** Dropping only the
  `Commit = tip^` check in enforce-lib (line 44 area) passes all 48 scenarios.
  The check itself works: my B1 attack above was refused by it alone. Add a
  scenario that isolates it. The tip commit changes only `verdicts/<ID>.md`, its
  Commit names an older commit, and later commits sit below it, for example a
  MERGE verdict re-committed after a rework.

- **S-0-F2: quoted paths escape the path rules.** Git quotes non-ASCII paths in
  `git diff --name-only`, for example `"nucleus/v3/docs/\303\251.md"`. Such a
  path fails the `nucleus/v3/*` match, so enforce-lib treats it as "outside v3"
  and only requires P. A P-tier **non-spec** card adding `docs/é.md` was ACCEPTED
  by merge-card, while the ASCII control `docs/e.md` was refused. For S-tier
  verdicts the rule fails closed: they are refused as outside v3. In run_card.py
  the quoted names fail closed too, as outside Touch only. Fix it with
  `git -c core.quotePath=false` (or `-z`) in `changed()`, the tip `diff-tree`,
  check-core-paths and run_card.py. Add a non-ASCII docs scenario.

- **Trust limit**, documented in verdicts/README.md: verdict authorship is not
  authenticated, so an orchestrator could forge a verdict. That is acceptable
  for now.

Before running merge-card, the orchestrator must add S-0-F1 and S-0-F2 to
QUEUE.local.md as `- S-0-F<n> | queued | P | ...`. merge-card requires both
entries.
