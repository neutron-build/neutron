## Findings
**F1. ESCALATE 2 is now measured: the daemon route is open.** From inside the container, `systemd-run --user --wait --pipe --quiet podman version` printed `5.4.2`, so a process started in the user manager, outside the namespace. This is the owner's approved podman-only form, and the only form I ran that way; the mechanism is not podman-specific (by reading). Connect-only probes, nothing sent, also reached `/run/user/1000/bus`, `systemd/private`, `sway-ipc.*.sock`, `openssh_agent`, `wayland-1`, `pipewire-0` and TCP 127.0.0.1:22, :3773 and :36667 (`routes.txt`). `swaymsg exec`, `ssh` and the T3 port were not exercised.

**F2. Files are the third open route, and the worst one.** `~/.cargo/bin`, `~/.local/bin`, `~/.bashrc`, `~/.gitconfig`, `~/.ssh` and `cards/logs` are writable from inside. With a shim like the suite's on PATH, standing in for one a worker left in `~/.local/bin`, the probe passed and opencode ran uncontained: runner exit 0, `pass: true`, `FORGE LANDED`, and it persists across runs. So the test comment "nothing in run_card.py can switch containment off" is true of the file and misleading of the system: PATH is a production seam. The runner's bare `git` was already exposed the same way, and it runs outside the container. Non-blocking: it needs a deliberate worker, this card does not make it worse, and pinning `unshare` alone would not close the class.

**F3. Regression: PID-keyed temp paths collide.** Contained PIDs restart near 1, so paths keyed on `std::process::id()` in the shared temp dir lose their uniqueness (`bench/nbench/src/{digest,runner,vector,main}.rs`, `spikes/e1-*`). This is the measured worst case, equal PIDs, on the nbench test binary: **5 of 8 concurrent contained runs failed**, 0 of 4 uncontained, and 0 of 8 contained with a `TMPDIR` each. Sequential reuse of a stale directory passed 3 of 3. Real workers' PIDs only sometimes coincide, so expect rare flakes, not constant failures. The launch notes allow 4 runners. E4 has no such path. I removed the 48 low-PID directories my runs left in `/tmp/nbench-tests`.

**F4. Regression: NBench cannot start a server from a contained worker.** `systemctl --user` and `systemd-run --user --unit ...` fail inside with `Failed to connect to user scope bus via local transport: No data available` (outside, the same refused-unit call reaches systemd). That is systemd refusing a peer whose PID it cannot see (from memory of its source, not read). Only the `--wait --pipe` form works, so `podman::unit_start` and `unit_stop` fail from a tool shell. It fails loudly. NBench's unit tests still pass, and the B-0 family is merged, so I found no live worker this breaks. Acceptance stays outside the container until -F1, which must handle this.

**F5. Judgment call 1's cost is measured.** A tool shell orphaning 5000 processes left 5000 zombies under opencode (`oc/zombies.txt`), against a 47532 pids limit on the T3 scope. Accepted: see the contained-workers section, and -F3.

**F6. Two test gaps, code right by reading.** G3-INIT-AFTER-KILL passes the suite, yet a lookup after the kill misses the init 17 times in 100 on a real container, so the current order matters and nothing pins it. G3-FINALLY-GUARDED passes because the signal row calls `kill_child` directly; nothing covers `main()`'s finally for a SIGTERM during the init wait. Both rows go in -F1.
