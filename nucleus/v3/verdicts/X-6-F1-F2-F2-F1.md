## The GUC premise flake (implementer's observation)
The flake is real, its cause is known, and it is in the test, not the product.
- **Mechanism.** The env sets `core.trustctime true`. This git build compares ctimes in whole
  seconds, and `mv` changes the ctime of tools/, which `touch -r` cannot restore. So the
  `-c core.untrackedCache=true` premise (test-enforcement, "premise: GUC: a -c
  core.untrackedCache=true beats the environment") holds only when one wall-clock second covers
  everything from `guc_hide`'s `touch -d` through its two `git status` runs to the `mv`.
- **Under load.** That window crosses a second boundary, git rescans, and status shows
  `guc.py`. The premise then fails, closed: the hide did not work.
- **Probe (scratch repo, git 2.47.3).** I ran the same sequence under
  `-c core.trustctime=true -c core.checkStat=default`:
  - with no gap, it showed `gucz.py` 3/3 times (hidden);
  - with `sleep 1.1` before the `mv`, it showed `guc.py` 3/3 times.
- **Not this card's defect.** The row predates the rework, and trustctime defaults to true anyway.
  The refusal row (`guc_cp`) is timing-independent.

It needs a small test-only follow-up, below.
