```
The definitive database engine

Usage: nucleus [COMMAND]

Commands:
  start          Start the Nucleus database server
  init           Initialize a new Nucleus data directory
  version        Show Nucleus server version and build info
  status         Show status of a running Nucleus instance
  shell          Interactive SQL shell (psql-like REPL)
  backup         Back up a data directory to a portable snapshot (physical)
  restore        Restore a data directory from a snapshot created by `backup`
  dump           Logical (portable SQL) dump of every table — survives format/schema changes and replays through the constraint-safe executor, unlike the physical `backup`. Take it against a stopped or quiesced instance
  import         Import a foreign database into a Nucleus data directory, with a validation report itemizing every lossy decision. Sources: a postgres:// URL (live connection), a SQLite file path, or a .sql text dump path
  export         Export a Nucleus data directory as SQL text for PostgreSQL or SQLite, with a validation report itemizing any lossy type mappings
  load           Restore a logical dump produced by `nucleus dump` into a data directory (creates it if missing) by replaying the SQL through the executor
  restore-pitr   Point-in-time recovery: restore a physical base snapshot and replay the archived WAL (see `NUCLEUS_WAL_ARCHIVE_DIR`) forward to a target LSN, wall-clock time, or the latest archived point. Segmented-WAL databases only
  prune-archive  Delete archived WAL segments that lie entirely below an LSN
  help           Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version
```

## `nucleus start`

```
Start the Nucleus database server.

Without flags: standalone server mode. With --join: cluster mode, joins an existing cluster.

Usage: nucleus start [OPTIONS]

Options:
  -p, --port <PORT>
          Port to listen on (default: 5432)
          
          [default: 5432]

      --host <HOST>
          Bind address (default: 127.0.0.1). Use 0.0.0.0 for all interfaces
          
          [default: 127.0.0.1]

  -d, --data <DATA>
          Data directory for persistent storage
          
          [default: nucleus_data]

      --config <PATH>
          Path to a nucleus.toml config file. Defaults to <data-dir>/nucleus.toml. Use this to keep configuration outside the data directory, or to point one binary at different configs. A path given here must exist — startup fails rather than silently falling back to defaults, because a config that is silently ignored is worse than one that is absent

      --memory
          Use in-memory storage (no persistence). Useful for testing

      --join <JOIN>
          Join an existing cluster at this address (e.g., node1:5432)

      --cluster-listen
          Listen on the cluster port so other nodes can --join THIS node, even when this node itself joins nothing (the seed node of a cluster). Off by default: a single-node server opens no cluster port. Also settable via NUCLEUS_CLUSTER_LISTEN=1. Non-loopback listeners still require NUCLEUS_CLUSTER_TOKEN

      --region <REGION>
          Region tag for geo-distributed deployments (e.g., us-east, eu-west)

      --cluster-port <CLUSTER_PORT>
          Cluster communication port (default: 5433). Used for inter-node Raft messaging
          
          [default: 5433]

      --replicate-from <REPLICATE_FROM>
          Replicate from a primary node at this address (e.g., 192.168.1.1:5434). When specified, the server starts in replica mode and connects to the primary's replication port to receive WAL records via streaming replication

      --replication-port <REPLICATION_PORT>
          Port for the replication server (default: 5434). The primary listens on this port for incoming replica connections. Ignored in replica mode
          
          [default: 5434]

      --password <PASSWORD>
          Require password authentication. Can also be set via NUCLEUS_PASSWORD env var

      --auth-method <AUTH_METHOD>
          SQL authentication method when password auth is enabled. Defaults to SCRAM-SHA-256. (Cleartext is refused at startup -- accepted on the command line only for parser compatibility.)
          
          [possible values: scram-sha256, cleartext]

      --no-tls
          Disable TLS (connections will be unencrypted)

      --tls-cert <TLS_CERT>
          Path to TLS certificate file (PEM)

      --tls-key <TLS_KEY>
          Path to TLS private key file (PEM)

      --tls-client-ca <TLS_CLIENT_CA>
          Path to trusted client CA bundle (PEM) to require mTLS client certs. Can also be set via NUCLEUS_TLS_CLIENT_CA

      --encrypt
          Enable page-level encryption at rest (AES-256-GCM). Requires NUCLEUS_ENCRYPT_KEY env var (hex-encoded 32-byte key) or NUCLEUS_ENCRYPT_PASSPHRASE env var (passphrase for Argon2 key derivation)

      --compress
          Enable page-level LZ4 compression for on-disk pages

      --resp-port <RESP_PORT>
          Port for the RESP2 (Redis protocol) server (default: 6379). Set to 0 to disable the RESP server
          
          [default: 6379]

      --s3-port <S3_PORT>
          Port for the S3-compatible gateway (default: 0 = disabled). Requires NUCLEUS_S3_ACCESS_KEY and NUCLEUS_S3_SECRET_KEY
          
          [default: 0]

      --otlp-endpoint <OTLP_ENDPOINT>
          OpenTelemetry OTLP endpoint for distributed tracing. Example: http://localhost:4317 (gRPC) or http://localhost:4318 (HTTP). Requires the 'otel' feature to be enabled at compile time

      --max-memory <MAX_MEMORY>
          Maximum memory usage in MB. All subsystems (buffer pool, cache, KV, FTS, columnar) share this budget. Default: 512 MB
          
          [default: 512]

  -h, --help
          Print help (see a summary with '-h')
```

## `nucleus backup`

```
Back up a data directory to a portable snapshot (physical).

Refuses to run against a data directory a live instance holds: a plain copy of a database being written to is torn, and a torn snapshot that reports success is worse than no snapshot. Restore requires a build on the same on-disk format version.

Usage: nucleus backup [OPTIONS] --output <OUTPUT>

Options:
  -d, --data <DATA>
          Data directory to back up
          
          [default: nucleus_data]

  -o, --output <OUTPUT>
          Destination snapshot directory

      --force
          Overwrite the destination if it already exists

      --online
          Take a coordinated snapshot (checkpoint + WAL-pinned copy cut at a named LSN) by opening the database. Plaintext, uncompressed data files only — a plain copy needs no key, this does

      --allow-in-use
          Copy a data directory that a live instance holds. The result may be TORN; it is recorded as inconsistent in the snapshot's manifest

  -h, --help
          Print help (see a summary with '-h')
```

## `nucleus restore-pitr`

```
Point-in-time recovery: restore a physical base snapshot and replay the archived WAL (see `NUCLEUS_WAL_ARCHIVE_DIR`) forward to a target LSN, wall-clock time, or the latest archived point. Segmented-WAL databases only

Usage: nucleus restore-pitr [OPTIONS] --base <BASE> --archive <ARCHIVE>

Options:
  -b, --base <BASE>        Physical base snapshot directory (from `nucleus backup`)
  -a, --archive <ARCHIVE>  WAL archive directory (the per-database subdirectory of `NUCLEUS_WAL_ARCHIVE_DIR`)
  -d, --data <DATA>        Data directory to restore into. Must be empty unless --force [default: nucleus_data]
      --db-file <DB_FILE>  Primary data file name inside the data dir [default: nucleus.db]
      --lsn <LSN>          Replay through this exact LSN (inclusive). Mutually exclusive with --time; if neither is given, replays to the latest archived point
      --time <TIME>        Replay through the last segment archived at or before this Unix time (seconds). Segment granularity
      --force              Overwrite the data directory if it already exists
  -h, --help               Print help
```

## `nucleus prune-archive`

```
Delete archived WAL segments that lie entirely below an LSN.

Continuous archiving never removed anything, so an archive grows until the disk does not. This is the retention half, and it is deliberately manual: there is no policy and no timer, because deleting recovery data on a schedule -- with no knowledge of which base snapshots still exist -- trades a disk-space problem for an unrecoverable one. Pick the horizon from the `consistent_lsn` of the oldest base snapshot you still intend to restore from, and run `--dry-run` first.

Usage: nucleus prune-archive [OPTIONS] --archive <ARCHIVE> --keep-from-lsn <KEEP_FROM_LSN>

Options:
  -a, --archive <ARCHIVE>
          WAL archive directory (the per-database subdirectory of `NUCLEUS_WAL_ARCHIVE_DIR`)

      --keep-from-lsn <KEEP_FROM_LSN>
          Keep every segment that can serve a restore to this LSN or later. A segment is removed only when ALL of its records are below it

      --dry-run
          Report what would be deleted and delete nothing

  -h, --help
          Print help (see a summary with '-h')
```
